# 후속 실행 연결 활성화안 — 승인 대기

현재 활성화된 자동 대화 재개, 예약 서비스, 새 학습 작업은 없다. observe.py는 기존 상태 파일을 읽고 중복 없는 후속 요청 기록만 쓴다. 모델/셸/학습 실행과 commit/push를 호출하지 않는다.

고장 원인: 기존 48-fit 실행기는 train → seal → evaluate → finalize → archive를 모두 끝냈지만, archive 이후 다음 연구를 호출하지 않는다. 이전 별도 감시기는 구형 CLI 0.144.1을 호출해 현재 gpt-6-astra 호환성 오류가 났다. 현재 앱 CLI는 0.154.0-alpha.6.1이다.

승인받을 구체적인 범위:

- 현재 기존 대화 01a09586-d728-7432-b0f8-9d1641fc46cf와 같은 모델을 재개한다. 새 대화나 하위 에이전트를 만들지 않는다.
- 등록된 배치 완료/실행 오류 후 현재 사용자 turn 종료와 60초 유휴를 확인하고 결과 검토·다음 연구를 수행한다. 다음 실제 작업의 상태 파일 등록까지 확인한다. 종료 코드 0만으로 후속 연구 완료라고 선언하지 않는다.
- 범위는 이 TSFM PEFT 저장소와 기존 GitHub main의 연구 코드·실험·검증·결과 저장이다. 각 새 배치는 최대 64 fits / GPU 8시간, 이번 활성화는 최대 2개 후속 배치 또는 24시간이다. 그 뒤에는 명시적으로 예산 만료 상태를 기록한다.
- GPU 공유 lock, 외부 작업 대기, RAM/GPU guard, 과거 결과/소스 보존, 새 평가 분할 원칙을 유지한다. PASS가 나올 때까지 기준을 바꾸지 않는다.
- 기존 sandbox 및 자동 승인 검토를 유지하며 권한을 우회하지 않는다. 사용자 중단, 승인 거부, 예산 만료는 명시적으로 중지 상태를 기록한다. 후속 등록 누락/모델 오류는 최대 3번의 연결 복구 후 BLOCKED로 드러낸다. 완료된 fit은 자동 재실행하지 않는다.
- 재시작 시 중복 실행을 방지하는 영속 상태와 명시적 pause를 제공한다. 활성화 전 실제 전환 테스트와 현재 모델 호환성 사전점검을 한다.

자동 승인 검토가 지속적인 대화 재개와 후속 코드 수정·커밋·푸시의 승인 범위가 불충분하다고 거부했으므로 위 실행 부분은 아직 구현·설치·활성화하지 않았다. 실행 기능을 다른 경로로 우회하지 않는다.

기존 대화 재개는 [공식 non-interactive 문서](https://learn.chatgpt.com/docs/non-interactive-mode)의 `codex exec resume SESSION_ID` 기능을 사용하도록 설계한다. 이 기능 지원과 실제 이 계정에서의 후속 성공은 구분한다.
