# 왜 후보를 계속 바꾸기보다 기여의 근거부터 다시 잡는가

## 확인된 실패의 성격

이 문서는 과거 점수를 다시 PASS로 바꾸지 않는다. 최신 건물 비교의 원점수는 [component_contributions.csv](../building_peft_topic_decision_20260916/component_contributions.csv), 과거 전체의 분류는 [전체 재검토](../../research/full_reassessment_20260914/REPORT.md)에 있다.

- [확인] 최신 건물 120 fits는 실행·검산을 마쳤다. 선택된 세 방법은 모두 ZERO로 동일했다. 고정120의 표준 LoRA는 F0보다 평균 주지표5.811% 좋았으나 건물 bootstrap 구간은 −4.138~22.853%로 불확실하다. 'LoRA가 전혀 작동하지 않는다'는 결론과 다르다.
- [확인] 같은 고정120에서 균일 보존은 표준 LoRA보다1.633% 나빴고, 방향별 보존 후보는 균일 보존보다0.346% 나빴다. 이 조건에서는 추가한 구성요소의 이득이 확인되지 않았다.
- [확인] H3/H14 학습 창은2/13개, 건물별 평가 원점은1개였다. [추정] 이 정보량으로147456개 LoRA 파라미터를 적응하고 네 개발 건물에서 설정까지 정하는 것은 불안정할 수 있다. 파라미터 수와 창 수의 비율만으로 실패 원인을 증명하지 않는다.
- [확인] 채널 공유 실험은 electricity에서 LH가 가장 좋은 학습군이었고 traffic에서는 단순 계절 반복이 더 좋았다. 모듈을 줄인 효과와 LoRA보다 좋은 예측 효과는 별개다. MOMENT 파일럿의 INIT는 새 예측 head를 포함하므로 사전학습된 zero-shot forecasting과 같지 않다.
- [확인] 초기 진단 중에는 실제 학습을 하지 않은 신규성·자원·수치 중단도 있다. 이들을 예측 성능이 나빴던 실험과 합쳐 '모든 PEFT 주제가 실패했다'고 말할 수 없다.

## 지금 좁힐 연구 질문

[설계] 먼저 '사전학습된 시간 표현을 유지하면서 채널 적응을 추가할 때, 단순 LoRA+head보다 추가 가치가 생기는가?'로 좁힌다. 이는 새 논문 제목 확정이 아니라 다음 방법을 설계할 근거를 만드는 문제다. 짧은 건물 이력의 보존항을 다시 조정하거나, 이미 사용한 잠금 건물을 미노출 평가처럼 쓰지 않는다.

이번 4-fit 대조는 표현 보존이라는 알려진 기능을 먼저 확인한다. 결과 해석은 다음과 같다.

1. 기존 SHARED만 이기고 LH를 못 이기면, 모듈의 불리한 경로를 완화했을 가능성은 있지만 채널 모듈이 필요하다는 근거는 부족하다.
2. 같은 원천 두 seed에서 LH까지 이기면, 해당 조건의 개발 신호로 기록한다. 독립 미사용 자료와 가까운 선행 대조 없이는 방법론 주제 확보가 아니다.
3. 둘 다 못 이기면, 이 경로 수정도 설명력이 부족하다. 동일 데이터를 보며 gate·학습률·원천을 바꾸어 재도전하지 않는다.

다음 방법론을 제안하려면 실제로 남은 오류 구조, 가장 싼 대체 방식으로 설명되지 않는 효과, 가까운 선행과의 구체적 알고리즘 차이 세 가지가 함께 필요하다. 익숙한 부품을 조합하고 이름을 새로 붙이는 방식은 채택하지 않는다. 특정 범위로 목표를 좁히는 것은 가능하지만 결과가 좋은 조건만 뒤에서 골라 독립 PASS라고 할 수는 없다.

## 코드·연구 비판 검토

[확인] 신규 wrapper는 기존 SHARED_BUDGET의 주파수/채널/LoRA/head 초기화와 경로를 재사용하고 잔차 연결 및 스칼라 한 개만 추가한다. 기존 코드 수정은 없다. 학습과 checkpoint 선택은 기존 train/V origin 및 epoch schedule을 사용한다. 원래 R2 결과·캐시와 새 경로가 분리돼 있다.

[한계] 출력 교체→잔차 경로와 gate 초기화를 동시에 바꾸므로 개별 요인의 인과분해가 아니다. LH와 추가 모듈 간 파라미터 수가 다르므로 이 대조만으로 효율 우위를 주장할 수 없다. 기존 E를 이미 본 뒤 수행한 진단이므로, 같은 E의 양성 결과를 독립 검증이라고 부를 수 없다. frozen representation 자체를 정확한 과제용 표현이라고 전제하지 않는다. MOMENT의 새 head를 학습하는 문제와 Chronos의 native forecasting 보정 문제를 동일하게 묶지 않는다.
