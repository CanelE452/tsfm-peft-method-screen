0. 무엇을 이어가고, 무엇을 바꾸지 않는가
============================================================
[확인] additive_b0_adapter_v1_20260917의 C3는 Electricity SHIFT8에서
B0(C0) 대비 nMAE 3.962752%, 일반 어댑터 C2 대비 1.318388% 개선했다.
C3/C2의 반복 seed별 개선은 0.215471%, 2.392078%였다.
Electricity FAULT에서는 C0 대비 0.311674% 악화했고,
ETTm1 SHIFT8에서는 C0 대비 0.408978%, C2 대비 1.362384% 악화했다.
원래 E는 반복 사용한 개발 기간이다. 이 결과를 새 독립 검증으로 재명명하지 않는다.

[설계] 이번에는 C3의 구조/마스크를 다시 발명하거나 튜닝하지 않는다.
잘 학습된 B0를 동결한 상태에서 같은 C3를 유지하고 다음을 확인한다.
  Q1. 기존 네 전력 계열 밖에서도 C3의 추가 이득이 유지되는가?
  Q2. 이득이 단순한 수정량 감소/최근 위치 보호만으로 설명되는가?
  Q3. 기존과 다른 변화 크기·지속길이·패치 정렬에서도 어떻게 작동하는가?
  Q4. 다른 ETT 지점에서 같은 학습 절차를 재현했을 때 적용 범위는 어디까지인가?

[가설/미검증] 논문으로 이어갈 작업 가설:
  이미 적응한 예측기에 작은 잔차 어댑터를 추가할 때,
  관측된 지속성에 따라 추가 수정의 위치를 제한하면
  일부 지속적인 수준 변화 조건에서 일반 어댑터보다 유리할 수 있다.

이것은 '실제 사건을 판별한다', '입력 오류에서 항상 우월하다',
'학습 후 성능이 수학적으로 보존된다'라는 주장이 아니다.
당초 오류 강건성보다 지속 변화의 양성 결과를 보고 좁힌 후속 가설임을 명시한다.
후속 확인용 가설을 새 자료 채점 전에 고정하는 것이며 과거 결과를 확증으로 바꾸지 않는다.

소비처: 사용자와 지도교수가 이 한 방법을 논문 초안/정식 비교로 발전시킬지 판단한다.
작업명은 Persistence-masked residual adaptation으로 사용하되 신규성 확정 명칭으로 쓰지 않는다.

1. 목적–행동–예상 결과 연결
============================================================
A. 새로운 계열에서 가중치를 그대로 평가한다.
  왜1: 원래 네 계열에 맞춘 관찰인지 구분한다.
  왜2: 추가 학습 없이 현재 모델의 적용 범위를 확인한다.
  조건: 계열 선정에 미래 오차를 쓰지 않고, 기존 출발/선택 가중치를 변경하지 않는다.
  예상: 같은 방향이면 계열 전이 근거. 반전하면 범위/표본 의존성이 남는다.
  독자의 질문: '원래 보던 데이터만 다시 본 것 아닌가?' → exposure manifest와 결과를 연결한다.

B. 동일한 어댑터에서 마스크의 평균/위치/최근성만 통제한다.
  왜1: 추가 용량과 단순 보정 강도를 배제한다.
  왜2: 지속성 위치 정보가 꼭 필요한지 확인한다.
  조건: 원래 C3 수식은 그대로 두고, 대조군의 정보와 예산을 맞춘다.
  예상: C3가 대조를 넘으면 위치 정보의 추가 근거. 같으면 단순 대안을 채택한다.
  독자의 질문: '그냥 약하게 보정하면 되지 않나?' → MEAN/SHRINK/RECENCY가 답한다.

C. 고정된 스트레스 범위를 확장한다.
  왜1: SHIFT8·32개 관측·패치 경계 하나의 효과인지 확인한다.
  왜2: 지속하지 않는 경우의 반례와 식별성 한계를 확인한다.
  조건: 학습 자료는 그대로, 추가 평가는 선택에 사용하지 않는다.
  예상: 일부 범위에서 유지/붕괴하는 조건을 보인다. 모든 스트레스 승리를 요구하지 않는다.
  독자의 질문: '만든 변화 형태에서만 잘되는 것 아닌가?' → 형태/길이/크기 표를 제시한다.

D. ETTm2에서 동일 절차를 실행한다.
  왜1: 다른 관측 지점에서 방법의 전이 여부를 본다.
  왜2: ETTm1에서의 반대 결과를 숨기지 않고 적용 범위를 대조한다.
  조건: 원천·지점 관계와 이전 노출 여부를 먼저 공개한다.
  예상: 재현 또는 조건 경계. ETTm2가 나쁘다는 이유로 더 유리한 source로 교체하지 않는다.

가지치기:
  - 새 마스크/새 gate/새 backbone 탐색: 이번 질문에 직접 답하지 못하므로 제외.
  - 과거 v1/v2 A5/B5 재튜닝: 현재 B0 추가 적응 검증과 다른 문제이므로 제외.
  - 오류 평균을 새 주지표로 바꿔 통과시키기: 과거 가설과 현재 신호를 혼동하므로 제외.
  - 모든 데이터에서 우승 요구: 좁힌 조건의 방법 기여에 대한 필수조건이 아니므로 제외.
  - 그럴듯한 논문 초록 먼저 완성: 검증 전 기여를 단정하므로 제외.

3. 선행 경계 — 실제 읽고 표로 작성
============================================================
[확인] 아래는 준비 과정에서 확인한 1차 출처다. CLI에서도 원문과 공식 코드를 확인한다.
문헌 전체를 다시 무한 검색하지 말고, 핵심 다섯 편과 직접 충돌 후보 최대 다섯 편을 정리한다.

(1) Parameter-Efficient Transfer Learning for NLP (2019/ICML)
https://proceedings.mlr.press/v97/houlsby19a.html
  고정 백본에 작은 어댑터를 추가하는 큰 원리는 기존 방식이다.
  C2는 일반 bottleneck residual의 통제이며 공식 BERT 배치 전체 재현이 아니다.

(2) ReZero is all you need: fast convergence at large depth (2021/UAI)
https://proceedings.mlr.press/v161/bachlechner21a.html
  identity-start residual/gating은 기존 원리다. '0으로 시작' 자체를 새 기여로 쓰지 않는다.
  C3는 ReZero의 전체 architecture를 재현한 방법도 아니다.

(3) COSA: Context-aware Output-Space Adapter for Test-Time Adaptation in Time Series Forecasting
    (2026/ICLR)
https://proceedings.iclr.cc/paper_files/paper/2026/hash/2a8ce71baac4c89bf9ff479d8240c7d9-Abstract-Conference.html
https://github.com/bigbases/COSA_ICLR2026
  고정 예측기에 gated residual을 더하는 가까운 시계열 선행이다.
  COSA는 최근 도착한 정답을 사용하는 test-time adaptation이며,
  현재 C3는 offline 학습 후 동결된 patch-space residual이다.
  단순히 'gate가 있다'는 차이/일치만으로 신규성을 판단하지 않는다.
  학습 시점/사용 정답/보정 위치/조건 정보/평가 역할을 나란히 적는다.
  이번에는 평가 중 새 정답으로 C3를 업데이트하지 않는다.
  COSA의 온라인 절차를 바꿔놓고 정식 COSA 재현이라고 부르지 않는다.

(4) Adapt Data to Model: Adaptive Transformation Optimization for Domain-shared
    Time Series Foundation Models (2026/ICLR)
https://proceedings.iclr.cc/paper_files/paper/2026/hash/48c5226582f41254026748c7e35d4ac2-Abstract-Conference.html
https://github.com/thulab/TATO
  입력 변환으로 고정 모델을 적응시키는 직접 관련 대안이다.
  현재 C3는 raw 입력을 바꾸지 않고 이미 적응한 B0의 새 residual만 조절한다.
  고정 clip/Hampel 대조를 TATO 전체 탐색의 재현이라고 쓰지 않는다.

(5) On Over-fitting in Model Selection and Subsequent Selection Bias in Performance Evaluation
    (2010/JMLR)
https://jmlr.org/papers/v11/cawley10a.html
  반복 개발 E를 확증 자료로 세지 않는 이유. 새 seed만으로 선택 편향을 해결하지 못한다.

문헌 표 필수 열:
  논문/정식 발표 확인/문제/입력/적응 시점/학습 파라미터/보존 방식/
  이번 C3와의 실제 차이/정식 재현 여부/남은 비교.

이번 계약의 대조군은 기전 확인에 필요한 단순 대조다.
COSA/TATO의 정식 전체 비교와 다른 backbone 실증은 이번 본학습 예산에 포함하지 않는다.
따라서 결과가 좋아도 '정식 선행 전체를 넘었다' 또는 '논문 제출 준비 완료'라고 쓰지 않는다.
정확히 동일한 공개 방법을 발견하면 KNOWN_METHOD_COLLISION으로 기록한다.
그 경우에도 재현·전이 비교는 정해진 범위에서 수행할 수 있지만 새 방법 발견으로 세지 않는다.

4. 모델 계약 — 현재 C3를 그대로 유지
============================================================
[확인] pinned Chronos-Bolt-small revision:
  772f3d25d38aec6d914c8949dab4462e2d46f5d8
실제 로컬 snapshot/hash는 기존 receipt와 대조한다.

기본 모델 B0:
  raw observed input, q/v rank8 alpha16 LoRA, 추가 LoRA 파라미터294,912.
  기존 source/seed별 선택 B0 checkpoint를 사용한다.
  C0는 학습 안 된 foundation model이 아니라 이미 적응한 B0다.

추가 어댑터:
  512→8→512, bias포함 총8,712개.
  up weight/bias=0. 시작 예측은 B0와 동일.
  e_j는 원래 patch embedding, s=stopgrad(median_patch RMS(e)), floor1e-6.
  delta_j=s*tanh(W_up GELU(W_down e_j)).
  원래 B0 normalization/inverse, patching, head, reg token은 그대로.
  context512, horizon64, patch16, 32 context patches, quantile .1~.9.

지속성 마스크:
  m=median(x_obs), r=max(1.4826*median(|x_obs-m|),0.1*sigma_train).
  extreme_t=1[|(x_t-m)/r|>3].
  p_t=최근 최대8개 관측 중 현재 t와 같은 부호의 extreme 비율.
  t가 extreme이 아니면 p_t=0. context 왼쪽 경계에서는 창을 자른다.
  g_j=1-mean_{t in patch j} p_t.
  p/g는 observed context와 TRAIN sigma만 사용. 생성 상태/정답 사용 금지.

C0: B0 그대로, 추가 학습0.
C1: 같은 B0의 q/v LoRA만 추가 학습.
C2: B0 전체 동결, e_eff=e+delta.
C3: B0 전체 동결, e_eff=e+g*delta. 현재 제안 그대로.

C3를 출력 보정으로 바꾸거나, gate를 학습형으로 바꾸거나,
threshold/window/cap/rank/patch 크기를 튜닝하지 않는다.

5. 이번에 새로 학습하는 기전 대조 세 개
============================================================
세 대조 모두 B0 전체 동결, C2/C3와 같은8,712개 어댑터/초기값/학습 예산이다.
새 방법 후보가 아니라 C3의 설명을 반박할 수 있는 대조다.

M_MEAN:
  gbar=mean_j(g_j), 모든 patch에 같은 gbar를 곱한다.
  e_eff_j=e_j+gbar*delta_j.
  질문: 입력별 보정 총량을 줄이는 것만으로 충분한가?
  g의 합/평균은 C3와 같지만 g^2의 합은 일반적으로 같지 않다.

M_ROTATE16:
  32개 g를16patch 순환 이동해 적용한다. train/eval 모두 동일한 이동.
  e_eff=e+roll(g,16)*delta.
  질문: 동일한 mask 값들이 올바른 시간 위치에 있어야 하는가?
  gate 값의 multiset, 합, 제곱합은 C3와 정확히 같다.
  true shift 위치/미래 정답은 사용하지 않는다.

M_RECENCY:
  각 example의 g를 내림차순 정렬하여 오래된 patch→최근 patch 순으로 배치한다.
  작은 g, 즉 강한 수정 억제는 최근 patch에 둔다.
  질문: 관측된 지속 위치가 아니라 '최근 부분은 덜 건드린다'는 규칙으로 충분한가?
  gate 값의 multiset, 합, 제곱합은 C3와 정확히 같다.

중요:
  gate 분포를 맞춰도 delta와의 정렬, 최종 residual RMS, gradient 크기,
  서로 다른 최적화 경로까지 같아지는 것은 아니다.
  따라서 '순수한 인과효과를 완전히 분리했다'고 쓰지 않는다.
  실제 gate 통계/residual RMS와 직접 성능 비교를 함께 보고한다.
  학습한 C3의 gate를 사후로만 바꾸는 제거 실험은 보조다.
  주 기전 비교는 각 대조를 처음부터 같은 예산으로 학습한 결과다.

추가 학습 없는 강한 단순 대조:
  C2_SHRINK = q_C0 + alpha*(q_C2-q_C0).
  alpha∈{0,.25,.5,.75,1}; 같은 source/seed의 V objective로 한 값을 선택.
  exact tie는 작은 alpha. alpha0은 C0, alpha1은 C2와 정확히 동일해야 한다.
  새로운 계열 평가에서는 원래 네 학습계열의 V에서 고른 alpha를 그대로 이전한다.
  두 모델 예측을 쓰므로 두 forward 비용을 포함한다. 단일 forward라고 쓰지 않는다.

  C0_BIAS = q_C0 + beta*sigma_train.
  beta는 V의 다섯 선택 조건을 동가중한 (y-q_C0,median)/sigma의 중앙값 한 개.
  source/seed당 한 scalar이며 계열별 미래 정답 보정 금지.
  V에서 전체 관측수가 다르면 weighted median으로 조건 가중치를 맞춘다.

7. 공식 ETTm2 자료 준비와 시간 권한
============================================================
공식 출처:
https://github.com/zhouhaoyi/ETDataset
https://github.com/zhouhaoyi/ETDataset/blob/main/ETT-small/ETTm2.csv

공식 README에서 ETT-small은 두 변압기 지점 자료임을 확인했다.
README의 표본 간격 표현에만 기대지 말고 실제 CSV timestamp 간격을 검산한다.
ETTm1/ETTh1처럼 동일 지점의 해상도 변형을 완전히 독립 source로 세지 않는다.
ETTm2는 다른 지점이지만 같은 benchmark family다. 산업 도메인3개라고 세지 않는다.

로컬에 공식 파일이 있으면 hash/출처를 확인해 재사용한다.
없으면 공식 저장소 commit을 pin해서 한 CSV만 받는다. 임의 미러나 다른 dataset 대체 금지.
권한/네트워크 차단이면 해당 블록만 BLOCKED_DATA. 다른 완료 가능한 블록은 계속한다.

사용 컬럼:
  ['HUFL','HULL','MUFL','MULL']가 실제 CSV에 있는지 확인한 뒤 사용.
  모두 목표 univariate 계열로 pooled training하며 'OT forecasting'이라고 부르지 않는다.
  각 row를 independent univariate input으로 처리하는 기존 Bolt 경로를 유지한다.

분할:
  n=실제 행수. bounds=[0,floor(.6n),floor(.8n),n].
  기존 source와 같은 개발 프로토콜이며 통상 ETT benchmark split과 같다고 쓰지 않는다.
  TRAIN sigma는 raw prefix population std. context512/horizon64.
  학습/검증/평가 정답 horizon은 자기 role 범위를 넘지 않는다.
  V/E context는 원점 전에 이미 관측된 값이면 직전 role까지 걸쳐도 된다.

원점:
  TRAIN256, V64, E128 distinct full eligible index-days, 하루 하나.
  role의 합법 원점을 만든 뒤 해당 날짜의96phase 모두 합법인 full day만 남긴다.
  전체 full days를 count개의 strata로 나누고 각 strata의 midpoint day를 선택.
  phase roster=floor(k*96/count), k=0..count-1; role별 고정 seed로 독립 shuffle.
  ordinal day와 phase의 기계적 단조 연결을 만들지 않는다.
  256일을 확보할 수 없는 실제 자료라면 범위 부족을 보고하고 임의로 일수/주기를 바꾸지 않는다.
  이번 예상 자료는 각 role의 가능한 길이를 먼저 계산할 수 있으므로 GPU 전에 결정한다.

보고(성능 gate 아님):
  distinct days, full-day count, 분할별 시간범위/decile, phase histogram,
  7일 blocks, target overlap/unique timestamps, 결측 제외 수.
  위치별 count 차이는 full-day+roster 알고리즘상1 이하인지 unit test한다.
  데이터와 무관한 '상관계수 반드시0' 같은 요구로 실험을 차단하지 않는다.

8. 단계별 실제 실행과 정확한 학습 예산
============================================================
이 계약의 모든 데이터/마스크/선택/평가 조건을 먼저 고정한다.
어느 블록의 성능이 나쁘다고 다른 사전 승인 블록을 중단하지 않는다.
명백한 데이터 누출/계약 위반/자원 오류만 해당 범위를 중단한다.
새 결과에 맞춘 구조·seed·data 탐색은 승인하지 않는다.

[단계 A] 기존 C0/C1/C2/C3 가중치/예측 재사용 + 전이 패널 준비
  기존 두 source, 선택81550, 반복81551/81552 모델을 hash 검증.
  D_ELEC_TRANSFER 원점은 기존 electricity E128을 공통 사용.
  원래 네 계열의 V에서 C2_SHRINK alpha, C0_BIAS beta를 고정.
  신규 optimizer0. 전이 평가 정답은 아직 채점하지 않는다.

[단계 B] 원래 두 source의 세 번째 반복 seed 추가
  새 반복 seed81553. 결과에 따라 seed를 더 추가하지 않는다.
  source별 B0 LR는 기존 v2 선택81550의 선택값을 상속한다.
  새 B0를 동일 matched augmentation으로1024updates 학습하고 V로checkpoint선택.
  그 B0에서 C1/C2/C3를 각각 시작.
  세 추가군의 LR는 기존 additive 선택81550의 source별 값 그대로.
  source2×(B0 1경로 + C1/C2/C3 3경로)=8 fits.
  기존 반복모델을 seed81553이라고 이름만 바꾸지 않는다.
  C0의 새 B0 학습비용도 명시적으로 센다.

[단계 C] 기전 대조 M_MEAN/M_ROTATE16/M_RECENCY
  원래 Electricity/ETTm1, B0 source/seed별 동일 checkpoint 사용.
  선택81550에서 LR{1e-4,3e-4} 각1경로.
  반복81551/81552/81553에서 선택된 LR각1경로.
  2sources×3controls×(2선택+3반복)=30 fits.
  기존 C2/C3를 이 단계에서 다시 학습하지 않는다.
  LR선택·체크포인트 규칙은 아래 공통 계약 유지.

[단계 D] ETTm2 방법 재현
  새 selection seed85550, repeat85551/85552/85553.
  B0: LR2개선택+반복3개=5fits.
  C1/C2/C3: 각각 LR2개선택+반복3개=15fits.
  총20fits. 각 source/seed별 동일 B0에서 시작한다.
  M_MEAN/ROTATE16/RECENCY를 ETTm2에서 추가 학습하지 않는다.
  따라서 기전 대조의 외부 원천 재현까지 끝났다고 주장하지 않는다.

총 새 본학습:
  8 +30 +20 =58fits.
  58×1024=59,392 optimizer updates.

smoke(버리고 본학습에 넘기지 않음):
  원래2sources×(B0,C1,C2,C3,MEAN,ROTATE16,RECENCY)7group×2updates=28.
  ETTm2×(B0,C1,C2,C3)4group×2updates=8.
  합36updates.
전체 optimizer hard cap=59,428.

추론·분석·CPU alpha/bias 선택은 fit으로 세지 않는다.
기존 C0/C1/C2/C3의 과거 학습비용과 새 비용은 별도 장부.
추론만 끝난 경우 '58fits 완료'라고 보고하지 않는다.
차단된 블록의 미사용 예산을 새 후보에 옮기지 않는다.

9. 모든 새 학습의 공통 계약
============================================================
원래 v2 matched TRAIN cache 재사용: source별256days×4channels=1024examples.
32epochs, effective batch32,32updates/epoch,1024updates/fit.
매 example이 REFERENCE/POINT/BURST/SHIFT를 각각8회 보는 기존 상태 순서 유지.
POINT/BURST amplitude4/8/16, SHIFT4/8, duration24/48의 기존 schedule 유지.
ETTm2에서도 같은 generator 코드/상대 schedule을 적용하되 source key를 새로 고정한다.
원자료 입력/미래를 읽어 임의로 좋은 변형을 선별하지 않는다.

원래 source의81550/51/52 TRAIN 순서는 기존 additive와 같게 재사용한다.
새 seed81553과 ETTm2 seed는 동일 함수에 해당seed만 전달한다.
source 내 모든 방법은 같은 x/y/draw/order를 사용.
C3에게만 더 많은 큰 변화 정답을 제공하지 않는다.

FP32,TF32off,dropout0.
AdamW betas(.9,.999),eps1e-8,weight_decay0,gradientclip1,no scheduler.
C1도 optimizer moments0에서 다시 시작: 정확한 optimizer-state 이어학습과는 구분한다.
추가 어댑터 초기값은 대응seed에서 C2/C3/세 control 모두 같게 한다.
기존 B0 foundation/LoRA/head는 C2/C3/control에서 모두동결.

loss:
  native9quantiles의 원단위 prediction에 TRAIN population sigma로 normalized2pinball.
  현재 문맥 sigma나 손상된 sigma로 방법별 loss weight를 바꾸지 않는다.

checkpoint 후보 {0,256,512,768,1024}.
V objective=REFERENCE/POINT8/BURST8/SHIFT4/SHIFT8의 동가중 nMAE.
모든 새 모델에서 동일; SHIFT8만 최적화하도록 바꾸지 않는다.
선택용seed에서 LR별 best V, 다음LR선택. tie: 작은LR,이른checkpoint.
repeat seed는 정한LR에서 같은V규칙으로checkpoint선택.

step0선택=기존B0유지, 추가효과0. 실패한seed로 삭제하지 않는다.
선택epoch가 서로 다른 비교는 학습+선택 pipeline 비교다.
고정1024 상태도 부가로 보고하지만 E에서 더 좋은 쪽을 주표로 바꾸지 않는다.
공통LR/epoch는 제한된 기회 대조일 뿐 각방법의 전역최적화 완료를 뜻하지 않는다.

  기존E128중index순등간격64origins를 performance-free로선정.
  D_ELEC_TRANSFER,ETTm2에서도 core에동일64-origin보조패널 적용가능하며
  model/data선정은그결과에영향받지않는다.
  생성은관측원자료에서계산한r0를사용. +/−부호둘다동가중.
  다음8개변형을추가평가하되새학습에는넣지않는다:
    STEP6_D17, STEP6_D63, STEP12_D17, STEP12_D63,
    STEP8_D31, STEP8_D33, RAMP8_D32, PULSE8_D32.
  STEP: 최근D개에±a*r0를더하고미래64개에도동일delta.
  RAMP: 최근32개에0→delta선형증가,미래는delta가이어짐.
  PULSE: 과거는기존SHIFT8_D32와정확히같고미래delta는0.
  PULSE의과거/부호는SHIFT8의동일원점·채널·draw와맞춘다.
  그러면같은과거에다른미래가가능하므로 두상황을모두정확히맞히는것은요구하지않는다.
  생성상태는모델에주지않는다. 수학적반례이며산업사건레이블이아니다.

SHIFT8은이전개발에서양성으로선택된가설이다.
이번P1/P2채점전에주비교로등록하지만과거의사전가설이었던것처럼쓰지않는다.
새스케일12를잘맞췄다고범위를초월한일반강건성을주장하지않는다.
SHIFT과FAULT의발생빈도를현재혼합비로실제운영빈도라고해석하지않는다.

11. 원자료와 자연 변화의 처리
============================================================
원자료수정없음(REFERENCE)을모든패널에서필수보고한다.
자료가완전히clean이거나큰변화가모두실제사건이라고하지않는다.

12. 지표·추가효과·불확실성
============================================================
주지표: nMAE=mean(|q_.5-y|/sigma_train).
  각계열동가중,각origin동가중,두syntheticdraw동가중.
  평균원점수의비율로gain=100*(Err_baseline-Err_new)/Err_baseline.
  origin별퍼센트를평균한값과혼용하지않는다.
  F0로1정규화한지표가아니다.

원자료,FAULT(POINT/BURST6조건동가중),SHIFT4,SHIFT8,SHIFT_POINT를분리.
rawMAE,채널NRMSE,2pinball,quantilecrossing도보조보고.
원래9분위수를정렬해서median점수를사후변경하지않는다.

주효과는3층으로나눈다:
  C2 vs C0: 일반추가어댑터의효과.
  C3 vs C2: 이번규칙의추가효과.
  C3 vs C0: 최종pipeline의총추가효과.
분모가다르므로위개선율들을단순합하지않는다.

비교공정성:
  coreC1은동일추가학습기회대조이며C1step0결과도유지.
  C2_SHRINK와C0_BIAS는V에서선택한합법적추가보정대조.
  C3/MEAN/ROTATE16/RECENCY는같은8,712개추가파라미터.
  최종보유파라미터에는기존B0LoRA294,912개도포함된다.
  추가단계parameter수만으로전체학습비용을작게보고하지않는다.

불확실성:
  2000paired time-block bootstrap, fixedseed86700+고정panel/source ID.
  Electricity7*24slots, ETT7*96slots.
  같은dayblock을모든method/condition/seed/channel에함께적용.
  기존source4channels는고정,seed는평균후날짜재표집(조건부CI임을명시).
  D_ELEC_TRANSFER는time-block CI와추가series/group+time bootstrap을둘다보고.
  shared-weather상관이있으므로채널×시간을독립표본으로flatten하지않는다.
  optimizerseed3개의각효과를별도표시;날짜CI가seed모집단CI라고하지않는다.
  ETTm2와Electricityp값을합치지않는다.

확증언어:
  P1의SHIFT8 C3vsC0/C2 두대비를공동주질문으로고정.
  '일반어댑터보다추가가치'에는C3vsC2가필요하고C3vsC0도함께제시.
  기전3대비에는nominal95%와Bonferroni동시구간(alpha=.05/3)을함께표시.
  전체많은조건에서유리한한CI만골라통과라고하지않는다.
  반복개발선택/사전학습중복을CI가해결하는것은아니다.
  CI에0포함은불확실성이지동등성증명이아니다.

REFERENCE/FAULT의실사용허용손해는사용자가아직정하지않았다.
임의1%를논문합격선으로만들지않는다.
각손해의절대값·상대값·구간을같은표에보고하고Pareto tradeoff로설명한다.
모든조건에서승리할필요는없지만'오류강건성개선'같은넓은주장은그증거가필요하다.

19. 재사용 실패와 정확한 검사 범위
============================================================
기존 selected checkpoint가 없는 경우 보고서 점수나 base seed만으로 복원했다고 하지 않는다.
정확한 hash의 checkpoint를 기존 승인 cache/저장 위치에서 확보하지 못하면 그 source의
가중치 재사용 블록을 BLOCKED_BASELINE으로 남긴다. 옛 전체 실험을 새로 학습해 가중치를
만드는 것은 이번 예산에 포함하지 않는다. 독립적으로 준비 가능한 ETTm2 블록은 계속한다.

학습하지 않은 출발 B0에서 새 어댑터만 테스트했다고 쓸 수 없도록, baseline manifest에는
B0 학습원점·augmentation·seed·선택 checkpoint·원래 학습비용과 추가 단계의 비용을 분리한다.
실제 GPU 검산과 CPU 합성 검산, 일부 원점 scalar replay와 전체 원점 재계산을 구분해 적는다.
기록에 없는 정밀도·파일 내부 구조·다운로드 성공을 가정하지 않는다.
