0. 성공을 기다리는 루프 대신, 한 번의 유한한 연구 실행
======================================================================

실행 순서:
AUDIT -> 기존 증거 재검토 -> 표준 LoRA 개발 비교 -> TOPIC_ONEPAGE 봉인
-> 후보 1개와 단순 대조 1개 구현/개발 비교 -> 선택 봉인
-> 미사용 건물에서 고정 비교 -> 독립 검산 -> FINAL_DECISION.md.

최대 본학습:
- 개발 STD: 4건물 × 2이력 × 2학습률 = 16 fits.
- 개발 SIMPLE/CANDIDATE: 4건물 × 2이력 × 2방법 × 2학습률 = 32 fits.
- 잠금 평가: 6건물 × 2이력 × 3방법 × 2seed = 72 fits.
- 전체 최대 120 fits, 최대 19,680 optimizer updates.
  이는 120개 아이디어가 아니라 하나의 변경을 반복 조건에서 비교하는 횟수다.
- 실제 모델 smoke: 전체 최대 24 updates, 본학습과 별도 장부.
- 실패·중단한 fit도 attempt 상한에서 차감한다. 새 이름/seed로 대체하지 않는다.
- 후보를 정당화하지 못하면 STD 16 fits 이내에서 끝낸다.
- 비교군이 동일한 알고리즘·설정이면 같은 fit을 참조하고 고유 fit 수를 따로 센다.

전체 controller wall 상한 14,400초, GPU 누적 대기 상한 600초.
이 숫자는 실행 안전 상한이지 완료 소요시간의 약속이 아니다.
상한에 도달하면 부분 결과와 미실행 범위를 기록하고 종료한다.
자원 부족 때문에 검증/평가를 생략한 상태로 PASS를 만들지 않는다.

금지:
- PASS가 나올 때까지 새 후보, 새 데이터, 새로운 분할, 임계값을 반복 추가.
- 과거 STOP을 새 기준으로 소급 PASS 처리.
- 논문 주제를 이미 확보했다고 가정하고 그에 맞는 설명 작성.
- 간헐 수요, Censor, Query 수치 동등성, BASIS, source pooling/bank로 이동.
- '주말 현상이 3/4건물에 있어야 한다', 'LoRA가 F0에 먼저 져야 한다' 같은
  문제 가설 진입 gate를 새로 만들기.
- 더 이상 차별점이 없는데 알려진 방법에 새 이름을 붙이기.

3. 증거 재검토 — 새 GPU 학습 전에, 필요한 것만
======================================================================

과거 두 building 실험의 예측·학습 곡선·선택을 읽는다.
로컬 npz/checkpoint가 있으면 hash를 검증한 후 읽고, 없으면 보고서 근거만 사용했다고 표시한다.
파일이 없다는 이유로 과거 24/57 fits를 전부 재학습하지 않는다.

최소 네 가지를 EVIDENCE.md에 한 표로 남긴다:
1) 같은 H·건물·시점에서 F0/LOCAL/고정120/AFFINE의 raw와 scaled 오차.
2) 선택 설정과 고정120의 차이. 서로 다른 rank·seed·날짜면 직접 비교로 표시하지 않는다.
3) 예측 잔차의 하루 평균 편향과 평균 제거 후 RMSE.
   이 분해는 사후 진단이며 미래 편향을 입력으로 쓰는 배포 방법이 아니다.
4) 가능한 경우 학습량별 예측 변화. raw 출력과 공통 quantile 정렬 후 출력을 구분.

분해 공식(설명용 기호이며 기존 변수명이 아니다):
e_h = prediction_h - y_h, b = mean(e_h).
MSE = b^2 + mean((e_h-b)^2).
RMSE는 위 두 항의 합이 아님을 주의한다.
이 분해가 레벨/형상 변경의 인과효과를 입증하는 것은 아니다.

Oracle 해석 금지:
- 정답으로 골랐을 때의 최대 회복량을 실행 가능한 선택기 성능으로 쓰지 않는다.
- 후보 집합의 oracle을 모든 가능한 PEFT의 수학적 상한이라고 부르지 않는다.
- 미래 잔차·최선 checkpoint를 직접 알고 고르는 방법은 진단용으로만 표시한다.

기존 원점수의 더 유리한 지표만 선택하지 않는다.
H3/H14에서 분모가 달라 생기는 효과와 각 H 안의 방법 차이를 구분한다.

4. 한 장짜리 가설과 선행 비교 — 여기서 후보 하나만 확정
======================================================================

먼저 아래 세 설명을 검토한다. 이것들은 구현할 후보3개가 아니다.
- 설명1: 적응량/최적화 설정 선택이 건물마다 달라진다.
- 설명2: 규모·편향 보정과 시간 패턴 보정을 혼동하면 적응이 불안정해진다.
- 반대 설명: 새 PEFT가 필요하지 않고 기존 local LoRA+단순 보정으로 충분하다.
각 설명에 지지 관찰, 반례, 아직 없는 근거를 한 줄씩 적는다.
달력 상태만으로 원인을 확정하거나 source 정보의 필요성을 전제하지 않는다.

선행은 논문제목(연도/학회·저널)로 표기한다. 최대6개 1차 자료만 깊게 확인한다.
최소 다음을 출발점으로 사용하고, 선택할 변경과 직접 가까운 논문2개는 추가로 확인한다:
- LoRA+: Efficient Low Rank Adaptation of Large Models(2024/ICML)
- In-Context Fine-Tuning for Time-Series Foundation Models(2025/ICML)
- On Over-fitting in Model Selection and Subsequent Selection Bias in Performance Evaluation(2010/JMLR)
- 저장소 최신 PROTOCOL의 실제 전이/개인화 관련 선행 중 직접 관련된 것.

논문에서 확인할 항목:
문제, 데이터 접근 권한, 수식, 학습 파라미터, 가까운 대조군, 실제 평가 근거.
초록/검색 요약만으로 '이전에는 없다'고 단정하지 않는다.
원문 접근 불가면 출처와 미확인 부분을 명시한다. 학회 게재와 arXiv만의 공개를 구분한다.

후보의 허용 범위:
- 현재 target-only local LoRA의 학습 규칙 또는 보정 구조 한 부분만 변경.
- 새 source 사전학습, 검색 bank, 새로운 backbone, GPU 최적화, 대형 gating network는 불허.
- 후보와 핵심 대조는 동일 rank1 LoRA의 학습 파라미터 정책을 유지.
- 신규 trainable parameter가 꼭 필요하면 SIMPLE에도 실제 쓰이는 동일 용량을 부여해야 한다.
  그 비교를 이 계약의 세 학습군 안에 넣을 수 없으면 이번 자동 실행에서는 제외.
- LR/rank/학습량 튜닝, LoRA+, 균일 anchoring, 출력 convex mixture, OLS를 그대로
  새 이름으로 쓰는 경우 KNOWN_METHOD로 기록한다. 구현이 새롭다고 연구 방법이 새롭지는 않다.

새 후보는 관찰과 연결되고 다음 내용을 채울 수 있을 때에만 선택한다:
TOPIC_ONEPAGE.md (800단어 이내의 한국어 문서)
1) 문제 한 문장과 적용 범위.
2) 실제 관찰 두 개와 그 관찰만으로 아직 말할 수 없는 것.
3) 경쟁 설명/반례 하나.
4) 후보 수식·입력·학습 대상·추론 절차의 완전한 명세.
5) STD와 SIMPLE의 정확한 정의. SIMPLE은 후보를 가장 싸게 대체하는 방식.
6) 선행 두 개 대비 구체적인 차이. 동치/미확인도 그대로 기록.
7) 결과를 보기 전에 기대하는 예측 변화와 틀렸을 때의 행동.
8) 이 문서의 개발/평가 예산·지표·실행 조건.

MECHANISM_SPEC.md에는 구현자가 재량으로 채울 빈칸을 남기지 않는다.
새 상수는 최대2개, 값은 이때 train-only 근거나 선행으로 고정한다. 후속 grid 추가 불허.
수식상 후보와 SIMPLE이 핵심 조건에서 같으면 그 조건의 추가 가치를 주장하지 않는다.
예: c/(c+tau)는 c=0이면 항상0이다. F0 fallback보다 좋아질 수 없는 부분을 다시 목표로 삼지 않는다.

코드 리뷰와 연구 비판 리뷰를 각각 남긴다. 별도 agent가 없으면 메인 CLI가 두 역할을 순서대로 수행.
반례가 있으면 명세 수정은 최대1회, 새 후보로 교체는0회.
후보를 정당화할 수 없으면 NEW_METHOD_UNJUSTIFIED로 끝내고 STD 결과·주제 부족 원인을 보고한다.
후보의 큰 원리가 알려졌다면 성능 비교를 할 수는 있으나 최종 방법론 PASS와 구분한다.

실행 허가는 사용자의 이번 제한 실행 요청 범위다.
한 장을 작성했다는 이유로 사용자가 새 수식의 신규성까지 승인했다고 주장하지 않는다.
별도 추가 확인을 기다리는 무한 정지는 하지 않고, 범위를 벗어나면 이유와 함께 종료한다.

5. 이번 실제 데이터·모델 계약

데이터/모델을 새로 바꾸지 않는다:
- 기존 BuildingsBench v1.0.0 BDG-2 실제 시간별 전력 데이터.
- 모델 amazon/chronos-2, revision29ec3766d36d6f73f0696f85560a422f50e8498c.
- 타깃 이력 H={3일,14일}, 각 예측에 직전24h 입력 -> 다음24h.
- 노출된 H 안에 완전히 들어가는 context24/target24 창, stride24h.
- 완전 관측이면 학습 창은 각각 n=2,13.
- 현재 검산된 native 확률예측 loss, 출력과 지표 정책 유지.
- univariate target-only. 새로운 미래 날씨·다른 건물 시계열 입력 없음.
- 정상적인 숫자0을 결측으로 바꾸지 않는다.

건물 분리:
DISCOVERY = 최신 transfer 실험에서 이미 사용한 tune4 건물과 그 기존 origin.
이미 알려진 개발 자료임을 명시한다. 성능이 좋았던4개를 새로 골라서는 안 된다.
LOCKED = 이전 coverage 실험의 원래 heldout6.
로컬 노출 장부를 검사해 이6개가 이후 source/tune/dev/예측검사에 쓰였는지 확인한다.
이미 성능을 보았다면 잠금 평가로 부르지 않는다.
그 경우 새 평가 건물을 자동 대체하지 말고 LOCKED_DATA_EXPOSED로 종료한다.

LOCKED 원점:
기존 staged episode의 Wednesday/Saturday 중, canonical building_id 정렬의
짝수 위치는 Wednesday, 홀수 위치는 Saturday를 선택한다. 각 건물에서 H3/H14는 같은 origin.
선정은 기존 manifest의 ID/시간만 사용하고, 미래 load/점수로 고르지 않는다.
요일은 과제 선택 기준이지 실제 업무/휴무 운영표가 아니다.

과거 데이터 provenance 검사에서 결정된 연속관측 eligibility는 재사용한다.
새 지표를 보고 건물/날짜를 교체하지 않는다.
건물당 원점1개이므로 계절적 견고성을 주장하지 않는다.
동일 건물의 다른 meter/연도는 같은 물리 건물로 묶는다.
같은 사이트 공유·전처리의 전체기간 필터·사전학습 중복 가능성은 한계로 남긴다.

각 worker는 H 안의 과거와 모델 가중치만 받는다.
전체 타깃 시계열 핸들·미래정답·H 이전의 평균/표준편차를 받지 않는다.
미래정답은 DISCOVERY에서는 전역 설정 선택에, LOCKED에서는 선택 봉인 뒤 채점에만 사용한다.
LOCKED에서 per-target early stopping/학습률 선택에 미래정답을 쓰지 않는다.

6. 강한 단순 대조를 포함한 직접 비교
======================================================================

학습군은 정확히 세 개:
STD: 현재 검산된 local rank1 LoRA.
SIMPLE: TOPIC_ONEPAGE에서 고정한 가장 가까운 단순 대체 방법.
CANDIDATE: 유일한 제안 변경.

SIMPLE이 학습 없는 출력 보정이면 추가 GPU fit을 만들지 않는다.
SIMPLE이 STD와 같은 trajectory의 선택/출력만 바꾸면 fit 공유와 추가 선택 비용을 기록한다.
남은 fit 여유를 다른 후보 탐색에 사용하지 않는다.

공통 참조(추가 신경망 fit0):
- F0.
- 직전24h의 값 반복(SEASONAL24).
- 현재 코드의 positive affine OLS, 노출된 과거 창에서 F0 예측과 정답만 이용.
  OLS ill-conditioning을 몰래 다른 회귀로 교체하지 않는다. F0 fallback을 사전에 고정하고 발생수를 보고.
- candidate가 출력 혼합/anchoring 계열이면 uniform shrink/고정 보존을 SIMPLE에 반드시 포함.
- candidate가 학습률 비대칭이면 알려진 LoRA+를 직접 가까운 비교군으로 두고 신규성을 제한.
- candidate가 adaptive stopping이면 SIMPLE은 충분히 선택한 고정학습/일반 과거내 검증이어야 한다.

후보와 대조 사이 추가 정보·파라미터·탐색 횟수 차이가 있으면 명시한다.
같은 rank가 곧 같은 시간/메모리라는 주장 금지. 실제 비용을 측정한다.
새 방법만 STEP0를 빼거나 대조군만 너무 일찍 멈추게 하지 않는다.

공통 계산:
FP32, batch1, dropout0, TF32 정책 동일, AdamW betas(.9,.999),eps1e-8,weight_decay0,clip1.
rank1, alpha2, 기존96 attention projections, frozen native backbone/head.
기본 LoRA 학습 파라미터 예상147,456. 실제 목록·shape·numel로 재검산한다.
기존 rank8 결과는 역사적 참고이지 이번 동일예산의 새 점수라고 쓰지 않는다.
이번 결론은 rank1 예산의 파일럿이다. 모든 PEFT/rank에 대한 우위를 주장하지 않는다.

DISCOVERY:
4건물 × H3/H14 × 각방법 × LR{3e-5,1e-4}, seed61680.
H별 n개 학습 창에 같은 순열 stream을 반복.
checkpoint={0,n,4n,16n,120}의 중복을 제거해 정렬.
H3: {0,2,8,32,120}; H14: {0,13,52,120,208}.
각 fit을 가장 큰 checkpoint까지 수행해 조기 종료가 학습 기회를 다르게 자르지 않게 한다.
학습상한 도달은 수학적 수렴의 증명이 아니다.

선택:
각 방법에 같은 LR2개와 budget5종의 선택 기회를 준다.
budget 종류={ZERO,EPOCH1,EPOCH4,EPOCH16,FIXED120}.
LR와 budget 종류 한 쌍을 H3/H14 전체의 building-balanced 평균 primary로 선택한다.
H마다 별도 최적 recipe를 고르지 않는다. 종류가 epoch이면 실제 updates는 n에 따라 달라진다.
동률은 예상 적용 updates가 작은 것 -> LR가 작은 것.
ZERO가 선택되면 F0/해당 초기상태를 반환하고 왜 학습된 후보의 효과가 아닌지 보고한다.
각방법의 fixed120도 별도 고정 대조로 모두 남긴다. 평가에서 fixed120이 좋다고 사후 선택하지 않는다.

학습 없는 출력보정의 작은 grid가 필요한 경우 최대5개, 모든 값은 후보 명세 봉인 때 고정.
후보만 더 큰 탐색 budget을 주지 않는다.

위 선택은 개발 자료의 탐색이다. DISCOVERY의 이득을 독립 성공으로 발표하지 않는다.
선택에 대한 확신을 만들기 위해 작은 건물 수의 유의성 검정을 과장하지 않는다.

잠금 평가:
후보와 SIMPLE이 유효하게 정의돼 직접 개발 비교를 마쳤으면, 개발점수의 부호와 무관하게
계획된 LOCKED6 × H2 × 방법3 × seed{61680,61681}를 수행한다.
단, 구현/데이터가 무효하거나 후보를 연구로 정당화하지 못한 경우는 예외다.
'3/4 양수' 같은 사후 현상 입장 기준을 끼워 넣지 않는다.

각 평가 fit도 정해진 공통 trajectory 끝까지 실행해 선택 recipe와 fixed120을 함께 보관한다.
seed61681의 설정도 DISCOVERY seed61680에서 고정한 것을 사용한다.
평가두seed 결과를 보고 좋은 seed만 보고하지 않는다.

중요한 비용 구분:
- 실행한 trajectory의 총비용은 전체 연구비용.
- 선택 checkpoint까지의 비용은 배포 adaptation 비용.
- 같은 trajectory의 여러 예측점을 여러 fit으로 중복 집계하지 않는다.

======================================================================
7. 무결성 검사 — 연구와 무관한 인증 토너먼트로 만들지 않기
======================================================================

필수:
- native F0와 adaptation step0의 의미상 동일성(후보가 초기부터 다른 경우 차이를 명시).
- 동결 가중치/버퍼 불변, intended parameters 실제 업데이트, finite loss/gradient/output.
- B=0 초기화에서 첫 A-gradient=0일 수 있음을 허용. 모든 tensor의 매step nonzero 요구 금지.
- 후보 수식과 explicit 구현의 작은 FP64 출력/gradient 비교.
- 후보와 SIMPLE이 달라져야 할 합법 입력 반례에서 실제로 다른 동작을 할 수 있는지 검사.
  초기화 난수 차이만으로 '다른 메커니즘'이라고 하지 않는다.
- 미래정답을 바꿔도 입력·학습·선택에 영향을 주지 않는 target-poison 검사.
- checkpoint 저장 -> 새 모델 로드 -> 같은 FP32/eval 입력의 예측 재생.
- 정렬된 분위수의 중앙값 위치는 실제 config의0.5에서 찾는다.
- raw output과 공통 정렬 output 둘 다 보존. quantile 평균을 조건부 평균이라고 단정하지 않는다.
- 주지표의 벡터식과 독립 float64 scalar 계산 일치.

서로 다른 batch shape/BF16/update 궤적 동등성은 이번 목적이 아니다. 실행하지 않는다.
실모델 허용오차는 현재 같은-shape FP32의 검산된 기준을 참고해 smoke 전에 명세한다.
원출력의 단위만으로 오류를 판정하지 않고 normalized 출력과 참조 크기를 함께 본다.
실패 후 값만 올려 통과시키지 않는다. 의미/코드 오류 수정은 기록하고 최대1회 재검사.
24 smoke updates 안에서 해결되지 않으면 INCONCLUSIVE_IMPLEMENTATION.

======================================================================
8. 지표와 선택 기준 — 주제의 이름을 지표에 맞춰 바꾸지 않기
======================================================================

Primary는 최신 building 연구와 동일:
각 episode의 next24 median RMSE / 노출된 H일 history의 population std(floor1e-6).
건물마다 H3/H14를 같은 비중으로 평균하고, 건물 평균을 다시 같은 비중으로 평균한다.
두seed는 각 건물 안에서 평균한다. 24시간/seed/두history를 독립 건물로 세지 않는다.

Secondary:
raw RMSE·MAE, history-scaled 2-pinball, H3와H14 별도 성능,
F0 대비 증가/감소, 실제 update/시간/메모리, 최악 건물 및 건물별 성능.
건물간 raw RMSE 평균은 대규모 부하의 영향을 받는 별도 집계다.
primary와 raw의 순위가 다르면 둘 다 공개한다.

비교군b 대비 후보 개선율:
G_b =100*(L_b-L_candidate)/L_b.
먼저 각방법의 같은 모집단 macro 원점수를 계산한 뒤 나눈다.
L_b=0이면 비율은N/A, 절대차로 보고한다. 분모에 임의 epsilon을 추가해 큰 이득을 만들지 않는다.
H별 개선율은 같은 H의 분모끼리 비교한다.
F0 loss를1로 보이게 하려면 loss/F0_loss라는 ratio라고 명시한다.

주 비교:
- CANDIDATE 대 선택된 STD.
- CANDIDATE 대 선택된 SIMPLE.
- STD fixed120, SIMPLE fixed120, F0, AFFINE,SEASONAL24를 모두 감사용으로 함께 제시.
평가에서 가장 좋은 고정 비교군을 확인할 수는 있지만 그 선택을 배포 정책이라고 하지 않는다.
그 최강 고정 비교군에 지면 '모든 단순 대안보다 좋다'는 주장은 금지한다.

불확실성:
LOCKED6의 물리 건물을 단위로 paired bootstrap2000회(seed61690).
H·seed·모든 방법을 같은 건물 resample 안에서 함께 유지한다.
95%구간과 leave-one-building-out의 효과 범위를 보고한다.
6건물·원점1개·동일공개원천이므로 작은 개발 확인이며 정교한 모집단 추정이 아니다.
사전학습 중복 가능성과 같은 site를 공유하는 한계도 그대로 남긴다.

======================================================================
9. PASS는 세 층으로 나누고, 하나의 상태로 조작하지 않기
======================================================================

(1) EXECUTION
COMPLETE / PARTIAL / INVALID / NOT_RUN.
구현이 돌아갔다는 것만으로 과학적 PASS라고 하지 않는다.

(2) PREDICTIVE_EVIDENCE
이번 운영상 SCREEN_PASS는 아래를 모두 충족하는 경우에만:
- LOCKED macro에서 선택STD와SIMPLE 각각 대비 상대 개선 >=1%.
- 두seed 각각의 macro 개선 방향이 두 핵심 대조 모두 대비 양수.
- 두 비교의 paired building bootstrap95%구간 하한이0보다 큼.
- H3 또는H14 어느 한 층의 macro가 두 핵심 대조 각각 대비1% 넘게 악화하지 않음.
- 현재 보고한 다른 단순 고정 대조가 후보보다 낮은 macro 오차를 내지 않음.
1%는 이번 투자판정용 실용 문턱이며 논문 채택 기준/보편 규칙이 아니다.
효과·CI·원점수를 항상 함께 쓴다. 이 문턱을 평가 결과를 보고 내리지 않는다.

양의 평균이 있으나 불확실성 또는 문턱 미충족:
POSITIVE_BUT_UNCERTAIN. '효과 없음'이라고 확정하지 않는다.
한쪽 장점과 다른 쪽 손해가 있는 경우:
TRADEOFF_ONLY. accuracy만 목표인데 이를 다른 목적의 PASS로 바꾸지 않는다.
단순 대안이 같거나 좋을 때:
NO_ADDED_VALUE_IN_THIS_PILOT.
계산/데이터가 무효일 때:
INCONCLUSIVE_EXECUTION. 성능FAIL이 아님.

F0와의 관계:
F0를 먼저 이겨야 방법 비교를 열어주는 gate는 없다.
그러나 후보가 모든 적응군을 이겨도 F0보다 나쁘면 유용한 적응 향상이라 하지 않는다.
그 경우 '적응 손해 완화'로 주장 범위를 낮추고 위 실용SCREEN_PASS를 부여하지 않는다.

(3) NOVELTY
- DIRECT_EQUIVALENCE: 알려진 수식/알고리즘의 그대로 적용.
- UNRESOLVED: 직접 선행/차별점 검토가 부족함.
- DISTINCT_HYPOTHESIS: 선택한 구체적 차이가 남음. 최초성/논문 채택 보장은 아님.

최종 주제 판정:
- SCREEN_PASS + DISTINCT_HYPOTHESIS -> TOPIC_TO_ADVANCE 1개.
  '후속 투자할 방법론 후보 확보'이지 논문 완성/채택확정이 아니다.
- 양성이나 신규성 미확정 -> PROMISING_EFFECT_TOPIC_NOT_CONFIRMED.
- 알려진 방법만 좋음 -> KNOWN_METHOD_USEFUL_NEW_METHOD_NOT_FOUND.
- 불확실 -> TOPIC_UNRESOLVED. 부족한 근거를 한 문장으로 남김.
- 추가 가치 없음 -> NO_METHOD_TOPIC_THIS_RUN.

데드라인이 됐다고 최소1개를 강제로 선정하지 않는다.
주제를 바꾸거나 평가규칙을 재설계하지 않고 여기서 종료한다.

======================================================================
10. 운영·비용·기록
======================================================================

- 한GPU/한 worker. 현재 검증된 lock/guard를 읽고 재사용.
- Xorg 같은 graphics 프로세스를 학습 compute로 오인하지 않는다.
- 다른 프로젝트 PID를 종료하지 않는다. 과거 RustDesk 공존 승인을 새로 확대하지 않는다.
  현재 유효한 예외가 확인된 경우에만 기록하고 적용한다.
- 시작 안정30초, free>=4GiB; 실행 중 free<1GiB/비승인 compute면 안전경계에서 중지·대기.
- GPU 누적 대기600초, 전체wall14400초. 타임아웃이면 부분보고 생성.
- 전역 패키지/드라이버 변경, 비승인 데이터 전송, 자격증명 출력 금지.
- 안전하지 않은 OOM/nonfinite에 batch/모델/데이터를 몰래 바꾸어 재시도하지 않는다.
- 준비상의 경로/API 오류는 실제 변경과 기존 실패를 기록해1회 수정 가능.
  점수가 나쁜 fit을 '오류'라고 재분류해서 재시도하지 않는다.
- fit 완료를 단계별로 저장해 세션 종료가 전체 결과 손실로 이어지지 않게 한다.
  상태복원 가능한 동일run 재개는 재튜닝/새시도와 구분하고 원장에 남긴다.

존재하지 않는 옵션을 존재하는 것처럼 명령에 쓰지 않는다.

======================================================================
11. 최종 보고서 — 독자가 한 번에 판단할 수 있게
======================================================================

FINAL_DECISION.md 첫 화면은 다음 여섯 항목만:
1) 최종 주제 후보 한 문장. 미확보면 '이번 실행에서 새 방법론 주제 미확보'.
2) 무엇을 바꿨고, 가장 가까운 선행과 정확히 무엇이 다른가.
3) 가장 강한 단순 대조와 핵심 원점수·효과·불확실성.
4) 실행 완료/실제fits/실제updates/미실행 범위.
5) EXECUTION / PREDICTIVE_EVIDENCE / NOVELTY의 개별 상태.
6) 다음 결정 하나: 계속/보류/종료. 새 실험 자동 실행 없음.

REPORT 질문 체인:
무슨 문제인가 -> 왜 이 변경인가 -> 왜 이 대조군인가 -> 어떤 정보를 썼는가
-> 결과가 예상 변경을 지지하는가 -> 한계와 다음 결정은 무엇인가.
중간 논리가 끊기면 문장으로 봉합하지 말고 '남은 구멍'에 그대로 적는다.

실행 완료의 성공과 새 방법 발견의 성공은 서로 다르다.
전자는 정확하게 달성하고, 후자는 결과가 지지할 때만 선언한다.
