3. PRIORITY B — PatchPhase v2
======================================================================

기존 PatchPhase 결과는 보존.

기존 결과를 다시 FAIL/PASS로 수정하지 않는다.

하지만 기존 conditioning에는 구체적인 설계 문제가 있었다.

기존 phase feature:

    [sin(2π phase/16), cos(2π phase/16)]

기존 train:
    phase {0, 8}

기존 E:
    phase {4, 12}

에서는 train 시 sin component가 거의 항상 0인데,
E에서는 sin direction으로 구분해야 했다.

따라서 기존 gate의 모든 조건 방향이
train support에서 충분히 규정되지 않았다.

이것을 고친 v2를 새 실험으로 만든다.

이름:

    patchphase_v2_support_complete


----------------------------------------------------------------------
3.1 construct
----------------------------------------------------------------------

`patch_phase`를 integer phase 0..15까지 지원하도록 일반화.

반드시 모든 phase에서:

- 실제 336개 관측값 동일
- absolute timestamps 동일
- observation mask 정보 동일
- forecast origin 동일
- target horizon 동일

이어야 한다.

테스트:

    unpatch(patch_phase(x, phase)) == x

모든 phase 0..15에서 PASS.

패딩 때문에 정보량이 달라지면 안 된다.

masked padding만 허용.


----------------------------------------------------------------------
3.2 phase split
----------------------------------------------------------------------

Train phases:

    {0,2,4,6,8,10,12,14}

Validation unseen phases:

    {1,5,9,13}

Evaluation unseen phases:

    {3,7,11,15}

이렇게 하면 train phase-condition vectors가
sin/cos의 두 방향을 모두 span한다.

V와 E phase도 train에서 보지 않은 phase다.

canonical phase0 성능은 별도 clean-retention metric으로 보고한다.
unseen-phase primary 평균에 섞지 않는다.


----------------------------------------------------------------------
3.3 methods
----------------------------------------------------------------------

세 방법만 비교.

A. STANDARD_PHASE_LORA

- standard attention LoRA
- 같은 phase-augmented training contexts 사용
- 추가 output adapter 없음

B. PHASE_AUGMENTED_ADAPTER

- standard LoRA
- ordinary rank8 output/final-hidden adapter
- phase conditioning 없음
- proposed와 거의 같은 추가 capacity

C. PHASE_CONDITIONED_ADAPTER_V2

- B와 동일한 adapter
- phase sin/cos conditioning 사용
- train support가 full rank인 새 v2


세 방법 모두:

- 같은 phase sequence
- 같은 minibatch
- 같은 number of updates
- 같은 LR candidates
- 같은 V/E origins

을 사용.

----------------------------------------------------------------------
3.5 PatchPhase v2 결과
----------------------------------------------------------------------

보고:

- unseen V primary
- unseen E primary
- canonical phase0 primary
- per-phase losses
- prediction variance across phases
- selected LR/step
- seed별 contrast

핵심 비교:

    conditioned v2
      vs
    phase-augmented adapter

그리고:

    phase-augmented adapter
      vs
    standard phase LoRA


이전처럼 임의의 30% variance threshold 하나로 전체 아이디어를 닫지 않는다.

판정:

PATCH_V2_SUPPORTED
    - 두 seed 모두 conditioned primary가 phase-augmented보다 좋고
    - phase variance도 두 seed 모두 감소
    - canonical 성능의 큰 손해 없음

PATCH_V2_MIXED
    - 평균은 좋아도 seed 부호가 다르거나
    - primary와 phase variance가 서로 다른 결론

PATCH_V2_NOT_SUPPORTED
    - conditioned가 primary와 phase robustness 모두에서
      ordinary augmented adapter의 추가 가치를 보이지 않음

이 경우 현재 final-hidden phase-gating branch는 닫는다.

그 뒤 입력 patch-level v3를 자동 개발하지 않는다.

D. actual future loss

목적:

FR_REOPEN_POSSIBLE

FR_NO_ENTRY

    - regularizer가 실질적으로 작동할 조건 자체 없음

어느 경우든 이번 실행에서 FR GPU fit 시작 금지.


======================================================================
6. DIAGNOSTIC E — Censor loss의 tail-gradient 문제 확인
======================================================================

새 fit 0.

기존 Candidate07의
saved train predictions / checkpoints가 있으면 사용.

현재 censor CDF 구현에서:

예측한 upper tail 밖에서

    F(s) -> 1

이 되고,

    -log(max(1-F(s), 1e-6))

가 큰 값을 가지면서도
gradient가 0이 되는 구간이 존재할 수 있다.


실제 training censored positions에서 계산:

- total censored positions
- F(s) >= 1-1e-6 비율
- zero-gradient censor positions 비율
- 전체 censor loss 중 이 위치가 차지하는 비율
- sale lower bound와 predicted upper support의 거리

판정:

CENSOR_IMPLEMENTATION_LIMIT_MATERIAL
    실제 학습 위치 중 무시할 수 없는 비율이
    saturated zero-gradient tail에 있음.

CENSOR_LIMIT_RARE
    실제 데이터에서는 거의 발생하지 않음.

숫자를 그대로 보고.
사전에 임의의 성공 threshold로 잘라내지 않는다.

Material하면:
    corrected tail distribution/loss 설계가 필요하다고 기록.

하지만 이번 작업에서 자동으로 Censor v2 학습하지 않는다.

아래는 이번 재검토에서 새 GPU fit을 하지 않는다.

Freshness v1/v2:
    v2까지 수정 후 simple feature baseline보다 추가 가치 없음.

DualClock:
    360→1440 공정 연장 완료.
    같은 구조의 추가 학습만 반복하지 않음.

Maturity:
    복구된 구현에서도 quality/cost 모두 불리.

Calibration-weighted anchor:
    uniform/shuffled anchor보다 추가 가치 없음.
    basic uniform anchoring과 구분.

Block-shape:
    shape update는 실제 작동했으나
    block acceptance가 pooled/simple comparison을 넘지 못함.

Adaptive freezing / PROBE / overlap selector:
    이미 실제 비용을 포함한 strong simple control에 패배.

Global/local activation compression:
    가까운 simple compression 대비
    memory/gradient tradeoff가 구조적으로 불리.

Conditional Path:
    성능 FAIL이 아니라 novelty collision 문제.
    기여 차별화 없이 재학습하지 않음.

Context distillation:
    student failure가 아님.
    teacher headroom이 없어서 candidate training에 진입하지 않았음.
    현재 teacher 그대로 학생만 학습하지 않음.
