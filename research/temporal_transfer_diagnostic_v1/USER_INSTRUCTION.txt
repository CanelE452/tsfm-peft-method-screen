TSFM PEFT — 검증 이득의 시간적 전달 실패를 분해하는 CLI 실행 지시문
작성일: 2026-09-14
버전: v1.0
성격: 기존 결과의 정정 + 사후 개발 진단 + 제한된 국소 개입 실험

이 문서를 받은 CLI는 아래 범위 안에서 작업을 수행하라.
새 어댑터·학습형 selector·freezing controller를 발명하거나 학습하지 않는다.
기존 48-fit anchoring 연구를 다시 실행하지 않는다.
이번 작업의 기본 신규 fits=0, optimizer.step 호출=0이다.
필요 조건을 충족하면 저장된 체크포인트의 forward/backward와 복원 가능한
미소 파라미터 교란을 수행할 수 있다. 이것은 본학습이나 새 학습 성과가 아니다.
진단 후 새 학습을 하려면 별도의 계획 전체에 대한 사용자 승인이 필요하다.

======================================================================
0. 목표와 예상 산출물 — 결과를 먼저 정하지 말 것
======================================================================

최상위 목표:
시계열 파운데이션 모델의 적응에서, 강한 기존 방법으로 해결되지 않는 문제를
확인하고 그 원인에 대응하는 새 PEFT 방법의 필요성을 검증한다.
소비처는 사용자·지도교수의 다음 연구 선택이며, 아직 논문 우위 확증이 아니다.

이번 하위 목표:
“V에서 좋았던 적응이 다음 구간에서 나빠진다”는 관측을 다음 경쟁 설명으로
분해하고, 다음 실험이 무엇을 바꾸어야 하는지 하나로 좁힌다.

H1. 선택 효과: 특정 검증 창에서 고른 체크포인트의 순위가 다음 창에 전달되지 않는다.
H2. 보정 크기: 학습된 보정의 방향은 유용하나 크기가 과해, 단순 출력 축소로도 개선된다.
H3. 목적함수: native 학습 손실과 실제 평가 손실의 국소 개선 방향이 다르다.
H4. 시간별 보정 유효성: 같은 보정/국소 업데이트가 앞·뒤 구간에 반대 영향을 준다.
H5. 현재 정보 부족: 창 수·캐시·효과 크기가 부족해 위 설명을 구분하지 못한다.

H1~H4는 동시에 존재할 수 있다. 가장 큰 수치 하나를 골라 단일 원인으로 선언하지 않는다.
H4를 관찰해도 곧바로 distribution shift 또는 catastrophic forgetting으로 확정하지 않는다.
특히 백본을 고정한 HEAD에서도 실패가 관찰됐으므로, 전체 실패를 백본 표현 손상만으로
설명할 수 없다. 다만 JOINT에서 표현 손상이 일부 기여했을 가능성까지 배제되는 것은 아니다.

목적 트리의 가지와 실행 조건:

A. 기존 수치 감사
  목적 1: 잘못 계산된 개선율에 후속 설계가 의존하지 않게 한다.
  목적 2: 원래 예측·선택·판정을 보존하면서 보고 오류와 모델 오류를 구분한다.
  조건: 원점수→집계→판정 의존 경로를 재계산하고, 역사적 파일 해시는 보존한다.
  예상 결과: 오류의 영향 범위가 seed 열인지 전체 판정까지인지 판명된다.
  목적 지지: 지지. 최상위 연결: 간접 지원.
  독자 질문: “검산이 통과했는데 왜 보고 숫자가 틀렸나?” → 파생 집계 검증 범위를 설명한다.

B. 같은 예측에서 시간순 선택 대조
  목적 1: 모델 학습 차이 없이 선택 구간의 영향만 분리한다.
  목적 2: 새 제어기를 만들기 전에 단순 선택 대안과 후보 간 실제 차이를 확인한다.
  조건: 적응 학습 타깃은 선택·진단 구간 이전, 동일 후보 집합, 미래 진단값으로 선택 금지.
  예상 결과: 특정 선택 방식만 실패하거나 모든 방식이 비슷하게 실패한다.
  목적 지지: 결과별 부분/지지. 최상위 연결: 원인 후보 축소.
  독자 질문: “그냥 검증 데이터를 더 많이 쓴 것 아냐?” → 동일 창 수 대조와 분리해 답한다.

C. 고정 출력 축소 개입
  목적 1: 새로운 구조 없이 보정 크기만 줄여도 개선되는지 확인한다.
  목적 2: 학습 중 anchoring과 사후 출력 혼합을 같은 메커니즘으로 혼동하지 않게 한다.
  조건: 하나의 고정 체크포인트에 같은 alpha를 전체 채널·분위·미래 시점에 적용한다.
  예상 결과: 유효한 보정이 축소로 살아나거나, 0/F0 복귀 외에는 개선되지 않는다.
  목적 지지: 결과별 부분/지지. 최상위 연결: 복잡한 보존항 필요성 판단.
  독자 질문: “단순 shrinkage면 되는데 새 PEFT가 왜 필요해?” → 해결되면 구조 발명을 중단한다.

D. 제한된 gradient/미소 교란
  목적 1: 학습·평가 목적의 국소 불일치와 시간 구간별 불일치를 구분한다.
  목적 2: 관측 상관에 그치지 않고 동일 상태에서의 작은 방향 개입이 예측과 맞는지 본다.
  조건: 원본 가중치 보존, optimizer 미호출, FP32 재검증, E 접근 금지, 미소성 검사.
  예상 결과: 국소 방향 불일치가 재현되거나 이 설명의 근거가 없어진다.
  목적 지지: 부분. 최상위 연결: 후속 학습 개입의 근거이며 단독 논문 성과는 아니다.
  독자 질문: “이게 실제 Adam 업데이트나 장기 일반화의 원인이라는 증거야?” → 아니라고 명시한다.

가지치기:
- 새로운 PEFT 계열 전수 토너먼트: 이번 질문에 직접 답하지 않으므로 삭제.
- gradient가 충돌하면 곧바로 gradient surgery 적용: 인과성·선행 대비 차이 미확인으로 삭제.
- 같은 E를 이용한 anchor lambda 재탐색: 새 증거가 아니므로 금지.
- 손해 채널/기간 제거 후 성능 재보고: 금지.
- “진단만 반복”도 금지. 아래 A~D를 한 번 수행하고 증거·한계·다음 선택을 보고한 뒤 종료.

이 지시문의 경로와 기존 데이터의 실제 필드 이름은 구분한다. 읽지 않은 JSON 키,

아래 새 산출물 스키마는 새로 만드는 출력에만 적용한다.

기존 결과/선택 봉인/계약/학습 원본은 읽기 전용이다.
기존 보고 오류는 새 ERRATUM과 정정 산출물로 기록한다. 봉인된 과거 코드를 고쳐서
과거 source hash 검사를 무력화하지 않는다. 새로운 집계기는 새 namespace에 만든다.
과거 FAIL/STOP과 그 사전 기준은 유지하되, 버그가 판정까지 영향을 줬다면 원본 판정과
정정 판정을 나란히 보존하고 차이를 보고한다. 이를 새 실험 성공으로 세지 않는다.

네트워크 push/기존 브랜치 변경/외부 알림/자동 후속 연구는 이번 지시의 범위가 아니다.
완료 후 변경 목록과 실행 명령을 제공한다. 자동 commit/push를 전제하지 않는다.

GPU 조건:
- A~C는 기존 예측 캐시로 CPU 수행이 기본이다.
- D만 조건부 GPU 사용. 기존 프로젝트 락·GPU/RAM guard를 확인하여 재사용한다.
- 다른 작업을 종료하지 않는다. 외부 GPU 작업이 있으면 D는 실행하지 않고
  DEFERRED_GPU_BUSY로 보고한다. 끝없는 polling이나 기다림 기반 자동 후속 예약을 하지 않는다.
- 기존 한도를 완화하지 않는다. D의 추가 상한은 최대 12 checkpoint 상태,
  gradient backward 60회, forward 256회, optimizer update 0회다.
- 실패를 포함한 시도 횟수를 센다. 수치 문제로 설정을 바꾸는 자동 재시도는 없다.
- D wall-clock 안전 상한은 2시간. 이것은 실행 허용 상한이지 소요시간 예측이 아니다.
- 비유한 값·복원 실패·원본 해시 변동은 즉시 종료하고 실행 오류로 분류한다.

3. A — 보고 오류의 영향 범위를 먼저 확인한다 [신규 학습 0]
======================================================================

[확인: 소스에서 찾은 문제]
scripts/run_anchor_window_study.py의 seed_gains_percent에는 다음 식이 있다:
  100 * (1 / plain_loss * anchor_loss)
이 식은 개선율이 아니라 100 * anchor_loss / plain_loss다.
올바른, 낮을수록 좋은 손실의 대조군 대비 개선율은:
  G = 100 * (plain_loss - anchor_loss) / plain_loss
이다. 두 식을 혼동하지 않는다.

확인된 예:
- plain=anchor인 ETTm2에 현재 seed gain +100.000이 출력되어 있다.
  개선율은 0이어야 한다.
- Beijing 32의 기존 seed 열 99.736949..., 99.900216...는
  개선율로는 약 +0.263051%, +0.099783%다.
- Electricity 233의 기존 seed 열 100.974650..., 101.361990...는
  개선율로는 약 -0.974650%, -1.361990%다.

수행:
1) evaluation.json/봉인/fit 기록에서 source, budget, arm, seed 대응을 실제 키로 확인한다.
   zip 순서만 신뢰하지 말고 명시적 식별자로 pair join한다. 중복·누락은 오류다.
2) 캐시가 있으면 공식 score와 별도 scalar 구현으로 원점수를 재계산한다.
   캐시가 없으면 집계 원점수 감사까지만 하고 “예측 재검산 완료”라고 쓰지 않는다.
3) seed 개선율, seed 평균 손실 기반 cell 개선율, source-balanced macro,
   sparse-minus-dense interaction, 최종 decision을 각각 독립적으로 계산한다.
4) 평균 손실의 비율과 seed별 비율의 평균은 일반적으로 다르다. 둘 다 명명하여
   보관하되 기존 primary aggregation을 임의로 교체하지 않는다.
5) seed 오류가 최종 decision에 실제로 사용되는지 코드 의존 경로를 확인한다.
   사용되지 않았다면 “seed별 파생 집계 오류, 현재 확인한 최종 판정 불변”으로 기록한다.
6) 같은 방식으로 나머지 새 진단 산출물의 파생 수치도 테스트한다.

테스트 최소 조건:
  plain=1, method=1 -> 0%
  plain=1, method=0.9 -> +10%
  plain=1, method=1.1 -> -10%
  plain<=0 또는 비유한 수 -> 명시적 예외/undefined, 임의 epsilon으로 통과시키지 않음
  seed 순서 permutation -> paired 집계 불변
  duplicated/missing identifier -> 실패
  cell macro와 interaction -> 별도 수작업 식과 일치
  기존 원점수 비교 -> float64 절대오차 1e-10 이하(기존 계약에 더 엄격한 기준이 있으면 유지)

설명했다고 하지 않는다.

4. B — 같은 저장 예측의 시간순 선택 대조 [신규 학습 0]
======================================================================

목적은 선택 방식의 개발 진단이다. 새 selector 방법 논문을 만들지 않는다.

주 분석 대상:
완료된 anchor_window_study의 3 sources × 2 budgets × 2 seeds × 2 arms.
각 arm은 별도로 분석한다. native와 native_anchor를 섞어 하나의 oracle 선택기로
만들지 않는다. E는 새 후보 평가/선택에 사용하지 않는다.

현재 runner 기록에는 각 fit의 checkpoint trajectory와 V prediction/checkpoint 파일
참조를 남기는 코드가 있다. 실제 로컬 파일 존재·hash를 확인하여 후보 집합을 구축한다.
정해진 학습률 2개, 저장 step {0, 150, 450, 900}가 기준이다. 실제 저장 형식과 수는
manifest로 확인하고, 캐시 부재를 정상적인 후보 부재로 바꾸지 않는다.

후보 집합 원칙:
- 동일 arm/source/budget/seed 안에서 동일 후보 집합을 모든 선택 대조에 사용한다.
- step0는 중복 LR 항목을 한 후보로 취급하되 원본 identity를 보존한다.
- 그 밖의 동일 예측 후보도 duplicate group을 표시한다.
- 후보가 전부 같은 예측이면 NO_DISTINCT_CANDIDATES로 분류한다.
- 일부 후보 캐시가 빠지면 그 비교 cell을 BLOCKED_CACHE_INCOMPLETE로 둔다.
  좋아 보이는 남은 후보만으로 “전체 후보 실험”을 대체하지 않는다.
- V 전체로 선택한 역사적 checkpoint를 아래 D에서 독립 선택 결과인 것처럼 쓰지 않는다.

분할:
- 각 source의 기존 V origins 16개를 실제 시각/인덱스 순서로 정렬한다.
- S = 앞 8 origins: 이번 사후 분석의 선택용.
- D_diag = 뒤 8 origins: 이번 사후 분석의 시간적으로 나중인 진단용.
- 각 origin의 horizon 타깃이 S와 D_diag 사이에 겹치지 않는지 실제로 검사한다.
- 학습에 사용한 모든 타깃이 S보다 먼저 끝나는지도 검사한다.
- D_diag의 입력 문맥에 앞선 S 관측이 들어오는 것은 예측 시점에 이용 가능한 과거다.
  이를 미래 타깃 누출과 혼동하지 않는다.
- D_diag는 이미 기존 V의 일부로 사용된 구간이다. “새 holdout”이나 “독립 test”라고
  부르지 않는다. 연구자 수준의 재사용이 있으므로 결과는 개발 진단이다.
- origin 수가 실제로 16개와 다르면 자동으로 다른 분할을 발명하지 않는다.
  기준 차이를 보고하고 해당 항목은 실행하지 않는다.

선택 규칙(동일 arm 내에서만):
R0 FROZEN: F0를 그대로 사용.
R1 FIXED: LR 3e-5 / step150. 성능과 무관하게 사전 고정한 작은 적응 참조.
R2 RECENT4: S의 마지막 4개 origins에서 primary loss가 최소인 후보.
R3 SPREAD4: S의 0-based [0,2,4,7] origins에서 최소인 후보.
R4 ALL8: S의 8개 전체에서 최소인 후보.

R2 대 R3는 선택 타깃 수가 같다. 시간 배치/최근성은 다르다.
R4 대 R2는 검증 정보량도 다르다. 개선을 전부 안정성 메커니즘으로 돌리지 않는다.
정확히 같은 선택 점수는 이른 step, 낮은 LR, 안정된 후보 ID 순으로 결정한다.
필요한 origin·채널·마스크·scale은 기존 계약을 그대로 사용한다.

D_diag에서 보고할 것:
- 모든 규칙의 실제 선택 ID/step/LR, 선택 S 점수, D_diag 점수, F0 대비 이득.
- D_diag 앞4/뒤4 origins의 점수와 이득. 표본 수·유효 타깃 수도 함께 제시한다.
- S 개선인데 D_diag 악화인 사례 수. seed 중복을 독립 표본처럼 합치지 않는다.
- 후보의 S/D_diag 순위 일치, ties, 동일 모델 반환 비율.
- S 최선과 D_diag 사후 최선의 차이. 후자는 후보 집합 안의 낙관적 oracle
  진단이며 실행 가능한 모델 성능, 회수 가능한 이득 또는 성능 상한의 확증이 아니다.
- F0보다 좋은 후보가 없는 경우와, 좋은 후보는 있으나 선택하지 못한 경우를 구분한다.

부정확한 집계 방지:
metrics.py는 유효 타깃을 채널별로 집계하고 train scale로 나눈 뒤 분위·채널 평균을 낸다.
Beijing 결측 때문에 origin별 점수 단순 평균이 전체 score와 다를 수 있다.
원점수의 분자·분모를 저장해서 전체 재집계와 분해 합이 일치하게 하라.
채널에 유효 타깃이 0개인 블록은 제외 여부와 공통 채널 기준을 명시하고 조용히 비교하지 않는다.
분위 예측 정렬도 현재 score 규약의 일부다. 진단 전에 임의 변경하지 않는다.

기준 단위:
- 원점수와 paired 손실 차이가 primary다.
- 상대 개선율은 해당 비교군 손실이 분모다.
- %F0는 F0 손실이 분모인 별도 열이다. 두 비율을 같은 이름으로 합치지 않는다.
- 원천 간 raw loss를 그대로 평균해 순위를 만들지 않는다.
- seed는 최적화 반복, budget은 같은 정답에 대한 개입이다. 독립 원천 수는 3이다.
- S/D의 작은 origin 수로 확정적 유의성이나 동등성을 선언하지 않는다.

5. C — 학습된 보정의 크기만 바꾸는 개입 [신규 학습 0]
======================================================================

B와 같은 S/D_diag를 사용한다. 미래 성능에 따라 S/D를 바꾸지 않는다.
각 cell/arm에서 R2가 S로 고른 한 checkpoint를 고정한다.
F0와 adapted의 분위 예측은 각 모델에 기존 평가의 분위 정렬 규약을 적용한 뒤 혼합한다.

정의:
  q_alpha = q_F0 + alpha * (q_adapted - q_F0)
  alpha ∈ {0, 0.25, 0.5, 0.75, 1}

여기서 q는 분위 예측이다. 분위수 평균을 조건부 평균으로 부르지 않는다.
이 출력 보간을 확률분포 mixture나 학습 중 anchoring과 동일시하지 않는다.
LoRA weight를 alpha로 곱하는 개입과도 일반적으로 같지 않다.

실행:
1) 모든 alpha의 S/D_diag 손실을 계산해 한 곡선으로 보고한다.
2) S로 하나의 공통 alpha를 선택하고 고정해 D_diag에서 평가한다.
   ties는 더 작은 alpha를 고른다. 전체 채널·origin·horizon에 동일 alpha를 적용한다.
3) alpha=0이 F0, alpha=1이 원래 선택 예측과 정확히 일치하는지 검사한다.
4) D_diag로 alpha를 고른 값은 오직 사후 oracle 진단이며 모델 성능으로 내세우지 않는다.
5) alpha 추가 선택은 5개 후보의 추가 튜닝 비용이다. R2 대비 완전히 같은 선택 예산이라고
   주장하지 않는다. 이 결과는 단순 축소 대안의 개발 진단이지 새 PEFT 성과가 아니다.
6) 같은 규칙을 순수 native와 native_anchor에 별도로 적용한다. 좋은 arm만 남기지 않는다.

선택적 과거 참조(재학습/새 E forecast 없음):
mltimeseries Study35의 F0·HEAD·WIDE·JOINT 원본 예측이 현재 로컬에 있으면
그 저장된 예측에만 같은 고정 alpha 곡선을 계산할 수 있다.
그 구간은 이미 본 과거 개발 D이므로 설명용 반례로만 표시한다.
없으면 기록된 점수 비교만 사용하고 다른 설정의 HEAD로 재학습해 대체하지 않는다.

판독:
- S에서 고른 0<alpha<1이 D_diag에서 원모델보다 개선되고 F0도 넘으면,
  보정 크기/축소가 유효한 설명 후보다. 그 자체로 신규 손실 필요성을 지지하지 않는다.
- alpha=0만 유리하면 단순 적응 회피 가능성을 먼저 보고한다.
- 어느 alpha도 F0를 못 넘으면 이 선분 안에서 유용한 보정을 확인하지 못한 것이다.
  모든 비선형 적응이 불가능하다고 확대하지 않는다.
- 원천/시간블록별 최적 alpha가 달라도 이를 이용한 학습형 gate를 자동 구현하지 않는다.

6. D — 조건부 gradient 및 국소 교란 [본학습 0]
======================================================================

목적:
학습 손실의 국소 개선 방향과 평가 목적의 방향, 시간 구간별 방향을 구분한다.
이 부분은 기존 표준 방법의 재현이 아니라 이 프로젝트용 [미검증] 진단 조합이다.
유효한 미소 개입이 되어도 실제 Adam 장기 학습의 원인을 확정하는 실험은 아니다.

진입 조건:
- A 검산 통과.
- B에서 서로 다른 후보 예측과 시간 구간 간 차이가 수치 오차 이상 존재.
- C까지 완료하거나, C가 해당 없음인 구체적 이유가 있음.
- 아래 지정 checkpoint와 정규화/데이터/모델 revision이 모두 실제로 보존됨.
- 사용자가 이미 실행 중인 GPU 작업 없음. 환경 불일치는 BLOCKED.
- D는 old E 또는 새 E 배열을 읽지 않는 별도 loader를 사용한다.

고정 상태 선택(성능으로 고르지 말 것):
3 sources × dense233 budget × 2 seeds × {native, native_anchor}
LR=3e-5, step450의 저장 상태, 최대 12개.
이 조건의 체크포인트가 없으면 그 항목은 BLOCKED다. best/다른 LR/다른 step으로
대체하거나 trajectory를 다시 학습해 만들지 않는다.
이 고정 단계 분석은 배포 선택 모델의 효과가 아니라 학습 상태의 국소 진단이다.

대표 배치:
- 각 source의 train origins 중 시간적으로 가장 뒤의 2 origins를 T로 고정한다.
- S의 마지막 2 origins를 S_probe로 고정한다.
- D_diag의 마지막 2 origins를 D_probe로 고정한다.
- 모든 4개 원래 채널을 사용한다. 실제 결측/마스크 규약을 유지한다.
- 세 배치의 context/target 시각 및 train-only scale을 manifest에 기록한다.
- 성능/gradient 크기에 따라 origin이나 채널을 바꾸지 않는다.

동일 trainable-parameter 좌표에서 아래 gradient를 계산한다:
  g_native_T: T의 기존 native 학습 task loss
  g_eval_T:   T의 평가와 일치하는 differentiable scaled 2-pinball
  g_eval_S:   S_probe의 같은 평가 목적
  g_eval_D:   D_probe의 같은 평가 목적
  g_anchor_T:T의 기존 균일 F0 출력 보존항(계산 가능한 경우)

주의:
- native loss의 기존 reduction/정규화/분위 수 보정을 코드에서 확인한다.
- 평가 목적의 torch 구현은 metrics.py의 float64 score, mask, scale, 분위 정렬과
  작은 합성 예제 및 실제 배치에서 대조한다. 새 surrogate를 조용히 대신 쓰지 않는다.
- sort tie/비매끄러운 pinball 위치와 수치 불안정을 기록한다.
- norm=0 gradient의 cosine을 0으로 덮지 말고 UNDEFINED_ZERO_GRADIENT로 둔다.
- gradient norm/내적/cosine을 보고하며, 값의 양·음만으로 원인을 확정하지 않는다.
- train 정규화 때문에 미리 본 이후 정보를 쓰지 않았는지 검사한다.
- g_anchor와 task의 충돌 자체는 정규화 목적상 자연스러울 수 있다. 그것만으로 버그나
  새 수술 필요성을 선언하지 않는다.

국소 개입:
- 원본 checkpoint는 읽기 전용. 별도 메모리 복사본의 trainable 파라미터 phi만 교란한다.
- g_native_T 및 g_eval_T 각각을 정규화한 d=-g/||g|| 방향을 사용한다.
- s = max(1, ||phi||_2), epsilon ∈ {1e-4*s, 1e-3*s}를 사전 고정한다.
- phi' = phi + epsilon*d에서 S_probe, D_probe loss를 측정한다.
- 매번 동일 phi/RNG로 완전히 복원하고 checksum을 확인한다.
- 이 epsilon은 학습률 추천이 아니라 고정된 국소 진단 크기다. 결과를 보고 조절하지 않는다.
- actual optimizer.step은 호출하지 않는다. Adam momentum/variance 상태를 재현하지
  않았으므로 이를 실제 다음 Adam 업데이트 효과라고 부르지 않는다.
- 원래 BF16 결과와 FP32 진단의 차이를 먼저 기록한다. 국소 비교는 모두 같은 FP32
  환경에서 수행하여 BF16 반올림의 부호 변화를 과학적 결과로 오인하지 않는다.
- 직접 측정한 loss 변화와 1차 예측 epsilon * dot(g_eval_region,d)를 비교한다.
  두 크기에서 방향이 불안정하거나 근사가 부적절하면 NONLOCAL_OR_NUMERICAL로 표시한다.
  큰 epsilon에서만 이기는 결과를 채택하지 않는다.
- 저장 영구 가중치 변경 0, fit 생성 0, discarded perturbation 수 별도 집계.

판독 범위:
- native 방향은 평가 손실을 악화시키고 평가 목적 방향은 개선시키면,
  해당 상태·배치의 국소 objective mismatch 근거다. 전체 실패의 원인 확정은 아니다.
- 같은 방향이 S_probe와 D_probe에 반대 효과를 주면 국소 시간별 유효성 차이 근거다.
- 선택 모델의 반복적인 일반화 실패와 직접 연결하려면 별도 학습 개입 실험이 필요하다.
- 이 진단이 음성이어도 가설을 보편적으로 배제하지 않는다. 관측한 상태/배치 범위만 쓴다.

7. 최종 판정 — 고정 PASS 숫자를 새로 만들지 않는다
======================================================================

이번 작업은 원인 분해용 개발 연구다. 1%/3-seed 다수결 같은 보편 합격선을 두지 않는다.
아래 상태는 실행/근거의 분류이며 논문 합격 판정이 아니다.

NUMERICAL_ERRATUM_ONLY:
  파생 집계 오류가 확인됨. 영향 범위와 정정 여부를 보고.
SELECTION_TRANSFER_PATTERN:
  같은 후보 집합에서 선택 구간 변경에 따라 다음 구간 성능이 달라지는 관측이 있음.
SIMPLE_SHRINKAGE_EXPLAINS_PART:
  복잡한 구조 없이 S-only 선택 축소로 손해 일부를 회복하는 관측이 있음.
LOCAL_OBJECTIVE_CONFLICT:
  native/evaluation 목적의 국소 방향 차이를 실제 미소 개입이 뒷받침함.
LOCAL_TEMPORAL_CONFLICT:
  같은 국소 방향이 앞/뒤 구간에 반대 영향을 주는 근거가 있음.
INSUFFICIENT_EVIDENCE:
  작은 표본·동일 후보·불안정 수치 등으로 구분되지 않음.
BLOCKED/DEFERRED:
  파일·환경·GPU 사유. 과학적 FAIL이 아니다.

복수 상태를 동시에 허용하며 원천별 사례 수와 반례를 전부 보고한다.
수치 변화는 기존 score 재계산 오차와 비교해 기술한다. 1e-10을 실용적 효과 크기나
통계적 유의성 문턱으로 쓰지 않는다.

“선택이 원인이다”, “망각이 원인이다”, “새 PEFT가 필요하다”는 표현은
현재 근거의 관찰·해석·미확정을 분리하지 않고 사용하지 않는다.

======================================================================
8. 새로운 학습은 자동 실행하지 말고, 다음 한 개의 계획만 제안
======================================================================

이 단계에서 보고할 것은 다음 중 어느 방향이 가장 직접적인지다.
한 방향을 고르되 반증 가능성이 있는 대안도 함께 제시한다.

선택 패턴이 우세:
  동일 학습 궤적 + 시간순 다중 검증이라는 표준 대조가 다음 새 기간에서도 유효한지
  검사하는 bounded 계획. 학습형 selector/controller는 새로 만들지 않는다.

단순 shrinkage가 충분:
  복잡한 보존항/새 구조를 당장 만들 근거가 약하다고 보고한다.
  이전 shared-strength 실험과의 중복을 확인하고 새 이름의 재실험을 금지한다.

목적함수 국소 차이가 우세:
  loss 변경이 실제 장기 학습·미래 성능을 바꾸는 동일-budget 개입 계획.
  기존 native/raw 실험을 왜 반복하는 것이 아닌지 차이를 명시한다.

시간별 보정 유효성 차이가 남음:
  원인이 아직 미확정임을 유지하고, 단순 선택·축소 이후에도 남는 구체적 실패를
  대상으로 학습 개입을 설계한다. gradient conflict 관찰만으로 surgery를 정하지 않는다.

새 계획의 필수 제한:
- 최대 24 fits 안의 1개 질문만 제안한다. 이것은 제안 예산이며 실행 승인이 아니다.
- 기존 E를 또 최종 평가로 쓰지 않는다. 새 기간도 같은 원천인지 명시한다.
- seed를 독립 데이터셋 수로 세지 않는다.
- 어떤 결과가 나오면 그 개입의 필요성을 버릴지 예상 결과와 중단 조건을 적는다.
- 새 기법이면 1차 문헌에서 가장 가까운 기존 방법을 먼저 확인한다.
- 사용자가 전체 계획에 동의하기 전 학습하지 않는다.
- “이번 진단이 실패했으니 다음 후보 N개 자동 생성”을 하지 않는다.

======================================================================
9. PEFT 계열 실험 이력도 함께 정리한다 [문헌과 실행을 구분]
======================================================================

사용자는 LoRA 외의 PEFT를 실제로 시험했는지도 알고 싶어 한다.
현재 네 저장소의 접근 가능한 브랜치/파일에서 근거를 찾아 다음을 구분한다.

계열:
  원래 파라미터의 선택적 학습(bias/norm/일부 층)
  저랭크 가중치 보정(LoRA 및 변형)
  내부 additive/conditional adapter
  head/readout-only 적응
  soft prompt/prefix
  activation scaling(IA3 등)
  side network/독립 경량 경로
  representation intervention(ReFT 등)

별도 축:
  anchor/FR/검열 loss: 학습 목적의 변화
  freezing/probe/강도 선택: 업데이트·선택 규칙
  BF16/INT8/activation compression/checkpointing: 정밀도·저장·재계산 전략
  QLoRA: 저비트 백본과 LoRA의 결합. activation INT8 비교를 QLoRA 재현으로 세지 않는다.
  Full fine-tuning: 전체 학습 참조군이며 PEFT가 아니다.
  F0/무학습 예측 혼합: 그 자체로 PEFT 학습 방법이 아니다.

각 항목의 상태:
  TRAINED_AND_EVALUATED
  IMPLEMENTED_ONLY
  GRADIENT_OR_RESOURCE_PROBE_ONLY
  LITERATURE_ONLY
  NOT_FOUND_IN_INSPECTED_SCOPE

각 기록에 실제 코드 경로, 실행/결과 경로, 데이터·모델·학습 파라미터를 적는다.
논문 목록에 BitFit/FourierFT가 등장하는 것만으로 사용자가 직접 학습했다고 쓰지 않는다.
HEAD 구현을 원 논문의 Houlsby Adapter 재현으로, 조건부 scale gate를 IA3 공식 재현으로,
임의 hidden adapter를 ReFT 재현으로 자동 분류하지 않는다.
찾지 못했다는 것은 전체 과거에 없었다는 증명이 아니다. 검사한 브랜치/범위를 명시한다.
미시도 목록을 만든다고 그 계열 전부를 학습하지 않는다.

산출:
  peft_family_inventory.csv
  peft_coverage.md

10. 최종 보고 순서와 완료 조건
======================================================================

최종 보고서는 아래 질문 순서대로 작성한다.
1) 무엇이 문제였나: 원래 연구 주장과 실제 관측.
2) 왜 중요하나: F0보다 좋은 적응인지, 단순 대조보다 덜 나쁜 것인지.
3) 왜 이 대조인가: 선택·크기·목적·시간 효과를 무엇으로 분리했나.
4) 설정 근거는: 데이터 역할, 실제 코드, 기존 계약, 원천/seed/예산 구분.
5) 결과가 무엇을 지지하나: 원점수와 정정 비율, 반례 포함.
6) 무엇은 아직 모르나: 사후 V 재사용, 적은 origin, 국소 교란, missing artifact.
7) 다음 한 개의 계획: 무엇을 바꾸고 무엇이 나오면 중단하나. 자동 실행하지 않음.

추가 생성:
  REPORT.md
  execution_receipt.json
  next_experiment_proposal.md

execution_receipt에는 CPU 재집계 수, 실제 GPU forward/backward 수, 교란 수,
신규 fits=0, optimizer_updates=0, old/new E forecast 수, 역사적 파일 변동 여부,
실행 종료 코드·리소스·미완료 사유를 기록한다.
과거 저장 E를 읽어 감사한 것과 새로운 E 예측을 생성한 것을 분리해 센다.

결론은 다음 네 칸을 채운다:
  관찰 / 현재 지지되는 설명 / 배제하지 못한 설명 / 다음 행동

필수 테스트:
- 파생 개선율 단위 테스트와 원점수 재계산.
- S 선택 함수에 D_diag/E 점수를 바꿔 넣어도 선택이 바뀌지 않는 불변성 테스트.
- 시간 경계·horizon 타깃 중첩 검사.
- alpha endpoint identity, 동일 분위/마스크/scale 확인.
- D를 수행했다면 모든 perturbation 후 완전 복원 검사.
- 원본 파일/봉인/가중치 해시 불변.

그림은 문제·대조·결과가 정리된 뒤에만 만든다. 필수가 아니며 최대 3개:
  시간 구간별 후보 손실/선택 비교, alpha–손실 곡선, 국소 개입의 앞/뒤 효과.
이미지 장식이나 새 아키텍처 도식 제작으로 상류 미확정을 덮지 않는다.
