# 불확실한 미래 입력 PEFT — 실제 데이터 가용성 감사

[확인] **새 방법론 PASS는 아직 없다.** 이번에는 9월 13일 제안했으나 실행하지 않았던 미래 공변량 불확실성 문제의 실제 데이터부터 검사했다. 공식 예제의 한 타깃을 고정해 다운로드·시간 선택·독립 검산을 완료했다. 학습 0 fits, 업데이트 0, 모델 추론 0, GPU 사용 0이다.

[설계] 유지할 연구 질문은 **“여러 가능한 미래 외생변수를 처리해 얻는 확률예측의 추가 이득을 한 번의 조건부 PEFT 실행으로 옮길 수 있는가?”**다. 현재는 비싼 참조 예측의 이득도 미확인이다. 알려진 ensemble distillation에 LoRA를 붙인 것만으로 새 방법이라고 주장하지 않는다.

## 왜 이번에는 데이터부터 확인했는가

기존 MOMENT 결과에서는 표준 LoRA가 head-only보다 전력 5.794%, 교통 11.520% 평균 MSE를 개선했다. 새 attention prior는 같은 용량 SIDE보다 평균 1.007%, 1.423% 좋았지만 seed별 방향이 달랐고, LoRA 대비 교통은 3.668% 악화했다. 작은 신경망의 구조를 다시 바꾸는 것만으로 독립적인 개선 이유를 확보하지 못했다. [LoRA 대조](../../results/channel_head_only_20260916/REPORT.md), [attention prior](../../results/channel_attention_prior_20260916/REPORT.md).

[추정] 다음에는 먼저 기존 방법이 충분히 활용하지 못하는 입력 정보와 개선 가능한 예측 동작을 확보하는 편이 연구 질문을 분리하기 좋다. 이는 성공 확률이 수치로 검증됐다는 뜻이 아니다. 이전 Chronos 건물 실험과 MOMENT의 원인을 하나로 묶지도 않는다. 완료된 120-fit 계약과 원래 판정은 보존했다.

## 입력 계약에서 드러난 세 가지 한계

1. **예보 vintage는 곧 ensemble member가 아니다.** 같은 시각에 대한 서로 다른 날짜의 예보는 정보량과 예측 난도가 다르다. 관측된 가용시각 차이가 정확히 하루의 배수라는 사실도 진짜 동일 발행 cycle의 여러 경로를 증명하지 않는다. 이번에 읽은 카드·로더·튜토리얼에는 이 파일의 수집/생성 단계에서 실제 공개시각을 보장하는 로그가 없었다. 생성 코드가 어디에도 없다고 단정하지는 않는다.
2. **과거 실제 날씨의 공개시각이 없다.** 미래 날씨를 oracle 진단에 쓰는 것과, 과거 오차를 학습 시점에 합법적으로 알고 있었다고 주장하는 것은 다르다. 보수적인 지연을 설계할 수는 있으나 실제 배포 재현이라고 부르려면 근거가 추가로 필요하다. 현재 파일은 보정된 예보 오차 분포를 바로 만들어 주지 않는다.
3. **날짜만 비교하면 미래 예보가 섞인다.** 12월 27일 08시 원점에서 12월 28일 12시를 예측할 때, 12월 27일 12시 available_at 행(1.1805°C)은 아직 사용할 수 없다. 적법한 최신 행은 12월 26일 12시(3.65°C)다. 이 값은 예측 성능이 아니라 가용시각 검사의 실제 사례다. [여섯 행과 적법 여부](tutorial_availability_example.csv).

[추정] 따라서 모든 vintage의 단순 평균/분산을 '당시의 확률적 기상 예보'라고 넣으면 문제 정의부터 흔들릴 수 있다. 시점별 최신 행을 모은 경로 역시 단일 물리 예보 run임을 보장하지 않는다. 시간적 상관의 효용을 주장하려면 이 차이를 분리해야 한다.

## 무엇이 남았고, 어떤 조건에서 학습할 것인가

이번 상태는 **데이터 감사 COMPLETE / 예측 근거 NOT_EVALUATED / 신규성 NOT_EVALUATED**다. 원점수·자원 이득은 신규 모델을 실행하지 않았으므로 N/A이며, 0% 개선으로 쓰지 않는다. teacher/학생/LoRA 비교, GPU 시간·메모리 측정, 독립 원천 검증은 모두 미실행이다.

다음의 좁은 작업은 **가용성 근거를 갖춘 미래 입력 경로가 강한 단일 경로 예측·단순 보정보다 실제 proper score를 개선하는지 확인하는 것**이다. 먼저 실제 발행 자료 또는 명시적으로 모사한 정보 계약 중 어느 것을 검증하는지 고정해야 한다. 이 파일만으로 실제 앙상블이 확보됐다고 가정해 학생 PEFT부터 학습하지 않는다.

그 비교가 가능해지면 성능을 보기 전에 타깃·분할·결측 처리·경로 생성·비교군·예산을 고정한다. 동일 정보의 일반 LoRA와 단순 출력 분포 보정으로 충분하면 새 구조의 추가 가치가 없다. 참조 예측의 이득이 있어야 한 번의 조건부 PEFT로 압축하는 방법 연구가 정당화된다. 선행 검토와 실제 teacher 이득은 아직 남은 일이다. 이전 보고서의 제안 2~3%를 이미 등록된 성공 기준으로 쓰지 않았다.

## 검증·오류·재현 범위

기존 `.venv-channel`에는 pyarrow가 없어 설치 없이 기존 `.venv`를 사용했다. 첫 감사는 과거 날씨에도 available_at이 있다는 잘못된 스키마 가정으로 중단됐다. 그 열을 합성하지 않고 부재를 결과로 기록했다. 두 번째 감사는 원본 예보 DataFrame의 중복 index label 때문에 독립 검산기가 여러 행을 선택하는 오류로 중단됐다. 위치 기반 argmax로 수정했으며 실제 as-of 정책은 그대로다. 이후 완료했고 두 오류를 검증 기록에 남겼다. 학습 실패나 성능 실패는 아니다.

다운로드·선택 코드와 manifest·333원점 표·검증·이 보고서를 공개한다. 기존 자료 2,212개의 SHA256은 그대로다. scope hash와 실행 코드 hash를 남겼고 GitHub 공개 전 AST·원점 합계·결측 구간·12개 독립 검산·파일 hash를 재확인한다. 소스 코드 재현 명령:

```bash
.venv/bin/python experiments/covariate_availability_audit_20260916/audit.py
```

원자료와 공식 소스 캐시는 `.cache/covariate_availability_audit_20260916/`에 있다. 기존 캐시가 없으면 고정 revision에서 필요한 파일만 다운로드한다. GitHub 보고서만으로 원자료가 포함된다고 주장하지 않는다. 실행된 감사는 연구 준비의 근거이며 논문 주제 확보나 학습 완료의 대체물이 아니다.
