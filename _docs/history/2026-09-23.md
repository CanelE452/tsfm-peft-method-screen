**새로 드러난 교란 — LEARNING_SCALE_CONFOUND**
`_compute_loss` 의 `loss.mean(-1).sum(-1).mean()` 마지막 평균 분모가 행 수다.
공변량 행은 분자에 0 을 기여하지만(마스킹 정상) 분모에는 들어간다.
```

target+공변량 2행  batch=3  per_row=[1.271318, 0, 0]   scalar=0.423773
target_row/scalar = 3.0000 = batch
```
INPUT arm(FI/LI)은 상태를 행으로 넣어 같은 오차에 더 작은 scalar loss 를 받고 MOD arm 은 아니다.
두 축을 "순수 위치 효과" 로 해석할 수 없다. 본실험 전에 공통 보정 계약이 필요하다.

   `_compute_loss` 가 NaN 이 든 future_target 을 instance_norm→arcsinh 에 통과시킨다

### 데이터 축 원인 규명 — UPSTREAM_DNS_ZONE_UNSERVED

사용자가 직접 `GET https://api.boptest.net/testcases` 를 실행해 같은 실패를 확인해 줬다.
원인이 우리 망인지 서비스인지 갈라야 해서 1회 진단했다 (반복 polling 아님).

```
github/pypi/huggingface 해석 정상          이 PC 의 DNS 는 정상
api/www/apex boptest.net 전부 실패          zone 단위 실패
dig +cd 에도 SERVFAIL                      우리 쪽 DNSSEC 검증 문제 아님
+trace: .net -> cloudflare NS 2대 위임      등록은 살아 있음
그 NS 2대 직접 질의 -> REFUSED              zone 을 서빙하지 않음 (dangling delegation)
같은 NS 에 cloudflare.com -> NOERROR        서버는 정상, boptest.net zone 만 없음
Anthropic 측 WebFetch -> getaddrinfo ETIMEOUT  우리 망 밖에서도 해석 안 됨
```

결론: 전 세계 resolver 에서 해석 불가. 다른 망·다른 resolver 로 옮겨도 열리지 않는다.
`reason_code` 를 `DNS_RESOLUTION_FAILED` 에서 `UPSTREAM_DNS_ZONE_UNSERVED` 로 바꿨다.

정정: 직전 답변에서 "다른 환경에서 응답을 받아 전달하면 풀린다" 고 했는데 틀렸다. 그 경로는 없다.
