## BOPTEST 로컬 기동 — Docker 설치 후 첫 시도

사용자가 Docker 를 설치했다 (`docker.io` 29.1.3 / `docker-compose-v2` 2.40.3 / `docker-buildx`,
`systemctl enable --now docker`, `usermod -aG docker`).

### 그룹 반영 문제와 해결

`usermod` 은 새 로그인부터 적용되는데 이 세션의 셸은 그전에 뜬 프로세스라 옛 그룹을 물고 있어
`permission denied ... /var/run/docker.sock` 이 났다. 재로그인 대신 `sg docker -c "<명령>"` 으로
그룹을 재평가해 붙었다 (server 29.1.3 확인). 이후 모든 docker 명령은 이 형태로 실행한다.

### 실패 1 — minio 이미지 pull 거부

```
minio Error pull access denied for minio/minio, repository does not exist or may require 'docker login'
```

원인 분리:

```
docker pull hello-world                              성공   -> Docker Hub 접근 자체는 정상
docker manifest inspect minio/minio:RELEASE.2025-...  거부
docker manifest inspect minio/minio:latest            거부   -> 특정 태그가 아니라 저장소 단위
docker manifest inspect quay.io/minio/minio:RELEASE.2025-...  OK
```

`docker.io/minio/minio` 와 `docker.io/minio/mc` 가 2026-09-24 기준 태그 불문 인증을 요구한다.
같은 RELEASE 태그가 quay.io 에 공개돼 있어 버전을 바꾸지 않고 레지스트리만 바꿨다.

조치: upstream `docker-compose.yml` 은 건드리지 않고 `docker-compose.override.yml` 을 새로 만들어
`quay.io/minio/minio`, `quay.io/minio/mc` 로 지정했다. `docker compose config --images` 로 반영 확인.

## 과도응답 수집 — 실패 5회와 원인

`collect_transient.py` 를 돌리기까지 5번 실패했다. 원인이 전부 달라서 그대로 남긴다.

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | `pull access denied for minio/minio` | `docker.io/minio/minio` 가 태그 불문 인증 요구 (대조군 `hello-world` pull 은 성공) | `docker-compose.override.yml` 로 quay.io 의 동일 RELEASE 태그 지정 |
| 2 | `POST /select` → 500 | 본문 없이 `Content-Type: application/json` 을 보내 서버가 빈 문자열을 `JSON.parse` (`Unexpected end of JSON input`) | POST/PUT 은 최소 `{}` 전송 |
| 3 | `POST /select` 타임아웃 | 앞서 curl 로 만든 테스트를 stop 하지 않아 worker(1개) 점유 | `PUT /stop/{testid}` 로 반납 |
| 4 | worker 재시작 후에도 같은 타임아웃 | **재시작해도 큐가 안 비워진다.** 재시작 직후 죽은 실행이 남긴 유령 select 를 다시 집어 점유 (worker 로그로 확인) | redis 에 영속 볼륨 없음을 `docker compose config` 로 확인 → `down` 후 재기동으로 큐 소멸. 수집 전 "select 응답시간" 게이트 추가 |
| 5 | `PUT /results` → 400 | `oveHeaPumY_y` 등이 measurements 36종에 없음. 제어 신호는 `_u` 이름으로 저장된다 (`testcase.py __get_results`) | point 이름을 `_u` 로 교체. `/stop` 이 평문 `OK` 를 주는 것도 함께 처리 |

5건 중 4건이 내 쪽 오류였다(2·3·4·5). BOPTEST 자체는 정상 동작했다.

## 시상수 — 첫 계산은 폐기하고 다시 쟀다

처음 `estimate_tau.py` 로 낸 값(수온 tau63 = 9915s ≈ 165분)은 **시상수가 아니다.**
4시간 ON 구간의 마지막 값을 정상상태로 가정했는데 실제로는 4시간에도 정착하지 않는다
(304K → 313K 계속 상승). tau63 과 지수적합이 2~5배 어긋나고 실내온도가 격자 상한에 붙은 것이 단서였다.

10초 해상도로 다시 보니 응답이 세 겹이다.

| 성분 | 크기 | 시간 규모 |
|---|---|---|
| 전환 즉시 계단 | 수온 +5.48K, 전력 +3290W, 응축열 +14298W | 표본 1개 이내 (<10초) |
| 빠른 모드 | 수온 +4.47K / 20분 | 수온 tau 126s (R² 0.89), 응축열 tau 50s (R² 0.998) |
| 느린 모드 | 수온 304 → 313K | 4시간에도 미정착 |

### 연구 설계에 걸리는 함의

시간당 예측 격자에서는 빠른 모드가 보이지 않는다 — 한 스텝 안에서 계단과 tau≈2분 응답이 끝나고
남는 것은 수 시간짜리 완만한 램프다. "전환 과도응답이 어렵다" 는 전제를 쓰려면 어느 모드를
겨냥하는지 먼저 정해야 한다. 빠른 모드면 예측 간격이 분 단위여야 하고, 시간 단위면 difficulty 는
"느린 램프의 시작점 예측" 이 된다. 둘은 다른 문제다. 이 선택은 연구 방향 결정이라 여기서 멈췄다.
