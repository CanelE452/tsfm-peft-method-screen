# Frozen-past / forecast-token adaptation: first-seed actual-learning pilot

User authorized this next plan with explicit GPU occupancy monitoring. Preserve local-residual and all older results. This is a new restricted adaptation architecture, not an activation codec and not equivalent to all-token LoRA after training. No broad gradient screen precedes learning: only minimal correctness checks, then the fixed16-fit pilot. All hyperparameters and gates are in `configs/forecast_query_pilot.json`, committed before runs. One seed is development evidence, not robust confirmation.

## Architecture and budget

All arms have exactly1,179,648 trainable parameters and the same frozen native quantile decoder. Standard is rank8 attention LoRA with BF16 autocast and non-reentrant block checkpointing. Candidate uses the same96 rank8 attention projections, only on REG+3 forecast tokens. One complete frozen no_grad F0 encoder pass supplies each layer's history K/V and initial future tokens. The learned branch reruns native time attention for4 queries with fixed past K/V and learned future K/V, then native group attention and MLP only for4 tokens. Original absolute RoPE positions, key-validity masks and group masks are retained. The full frozen pass is bidirectional: this is not a causal prefix KV cache. Cache is fresh for every input window and released after its forward/backward; no label or other-window cache reuse.

Frozen-head control adds a residual768→768→768 SiLU forecast head with zero final matrix before the native output decoder. LST-style adapted control has12 layers of768→64 frozen-feature lateral projection;64-wide time/group attention sharing Q/K/V/O weights;64→224→64 feed-forward; final64→768 zero-initialized output. Nonlearned layer normalization. It processes all time tokens and reads full frozen layer outputs; its lateral weight gradients retain those features and all costs count. It is an adapted baseline, not official LST reproduction. All three new arms initially preserve F0 mathematically, subject to native-kernel/precision tolerance. Initial zero matrices intentionally delay other branch gradients until after the first update.

LST/query-only/token-activated adaptation precedents: [LST](https://papers.neurips.cc/paper_files/paper/2022/hash/54801e196796134a2b0ae5e8adef502f-Abstract-Conference.html), [Activated LoRA](https://papers.neurips.cc/paper_files/paper/2025/hash/4d0b6303d4a4811445f69f357bf6def5-Abstract-Conference.html), [EfficientFSL](https://arxiv.org/abs/2601.08499), [TS-Memory](https://arxiv.org/html/2602.11550v1). No claim of first query-only PEFT, new side-tuning principle or established novelty.

## Training/evaluation

Two datasets × four arms × two arm-appropriate learning rates × first seed =16 fits,240 updates each. Chronological59 training origins,11 validation origins and16 development evaluation origins; context4096, horizon48, first4 channels, batch2 independent windows grouped by4 channels. Identical per-seed window schedules across arms/recipes; native asinh-space objective and the same raw-scale probabilistic metrics. All methods get six validation checkpoints and two recipes. Include F0 evaluation. Select on validation and seal all dataset/arm winners before opening evaluation arrays. Prior exposure makes these development periods, not an independent holdout.

Measure actual optimizer-step allocated/reserved peaks, wall time including frozen forward/cache/branch/validation, parameter counts and selected nonzero checkpoints. Compare at fixed batch first. Success requires the query arm to improve on F0, remain within1% of standard's primary loss, reduce real peak by20%, and beat the best simple head/side primary loss by0.5%, on both datasets. If all selected steps are0, adaptation value is absent. Do not expand this candidate when the fixed-batch gate fails. No claim that gradient closeness proves forecasting quality.

## GPU protocol

RTX3080 10GiB; matching local CUDA wrapper. Own GPU lock; startup requires30 seconds with no external compute PID, at least4GiB free and utilization<90%. Record hardware used/free memory, utilization and process IDs at least every5seconds at step boundaries. Pause our loop if an external compute PID appears or free memory drops below1GiB. Existing per-step allocated/RAM/free guards apply. Full utilization by this job is normal and is distinct from exhausted VRAM. Never terminate another job or change system drivers. Monitoring and waiting time are reported separately from measured step compute.
