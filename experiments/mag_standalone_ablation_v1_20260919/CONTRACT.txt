# CLI 실행 지시문 — LoRA 선행 필요성 직접 검증
# experiment: mag_standalone_ablation_v1_20260919

현재 저장소: CanelE452/tsfm-peft-method-screen

이번 작업의 질문은 하나다.

> 현재 MAG가 정말 "LoRA로 먼저 적응된 B0 위에서만 유용한 second-stage PEFT"인지,
> 아니면 pretrained Chronos-Bolt-small에 LoRA 없이 MAG adapter만 바로 학습해도 유용한 standalone PEFT인지 직접 비교한다.

중요:
- 기존 `MAG_ONLY`는 "LoRA가 없는 MAG"가 아니다.
- 현재 `MAG_ONLY`도 LoRA가 학습된 B0를 기반으로 한다.
- 이번 실험에서는 혼동을 막기 위해 새 이름 `F0_PLAIN`, `F0_MAG`를 사용한다.
- 기존 B0/PLAIN/MAG checkpoint는 절대 재학습하지 않고 hash 검증 후 재사용한다.
- joint LoRA+MAG 동시학습은 이번 범위가 아니다.
- 결과를 보고 새 LR, 새 seed, 새 rank, 새 gate, 새 데이터, 새 threshold를 추가하지 않는다.

# 2. 새 비교군

새로 학습하는 것은 딱 두 군이다.

## A. F0_PLAIN

출발점:
- pinned `amazon/chronos-bolt-small` pretrained snapshot
- LoRA를 attach하지 않는다.
- backbone/head/normalization/patch embedding/encoder/decoder 전체 freeze.

추가 모듈:
- 기존 PLAIN과 정확히 같은 ResidualAdapter
- 512 → 8 → 512
- 8,712 trainable parameters
- up weight/bias = 0 initialization
- down initialization은 기존 PLAIN/MAG와 동일한 seed 규칙 사용
- gate = 1

수식:
`h'_j = h_j + a_theta(h_j)`

## B. F0_MAG

출발점:
- F0_PLAIN과 동일한 pretrained Chronos-Bolt-small
- LoRA 없음
- 전체 foundation weights freeze

추가 모듈:
- F0_PLAIN과 동일한 ResidualAdapter
- 같은 initialization
- 같은 8,712 trainable parameters
- 기존 MAG gate 수식을 그대로 재사용
- threshold, robust-scale floor, patch size를 절대 변경하지 않는다.

수식:
`h'_j = h_j + g_j(x) * a_theta(h_j)`

MAG gate:
- 현재 구현 그대로 median/MAD 기반 robust scale
- patch size 16
- 32 patches
- `abs((x-m)/r) > 3` 비율
- `g_j = 1 - extreme_fraction_j`

새 gate나 learned threshold를 만들지 않는다.

# 3. 반드시 재사용할 기존 비교군

새 학습 없이 기존 checkpoint/prediction을 hash 검증 후 재사용한다.

논문 표에서는 명칭을 다음처럼 통일한다.

- `F0` = pretrained Chronos-Bolt-small, no LoRA, no adapter
- `F0_PLAIN` = F0 + PLAIN adapter  ← 신규
- `F0_MAG` = F0 + MAG adapter      ← 신규
- `B0` = F0 + 기존 LoRA
- `B0_PLAIN` = 기존 `PLAIN`
- `B0_MAG` = 기존 `MAG_ONLY`

필요하면 C3/TOKEN_GATE/PETSA 결과는 보조 문맥으로만 링크하고,
이번 핵심 질문의 primary family에는 넣지 않는다.

# 4. 구현 시 가장 중요한 검사

새 F0 기반 build 경로에서 절대로 `attach_lora()`를 호출하지 않는다.

실제 모델을 만든 뒤 아래를 assert한다.

### F0
- trainable parameter count = 0
- LoRA parameter/module name = 0개
- 기존 pinned pretrained snapshot hash 일치

### F0_PLAIN / F0_MAG
- trainable parameter count = 정확히 8,712
- trainable parameter names는 adapter에만 존재
- LoRA parameter/module name = 0개
- foundation model parameter/buffer 전부 frozen
- source/seed가 같을 때 PLAIN과 MAG의 adapter initial state는 bitwise identical
- 학습 시작 step0에서:
  - F0_PLAIN prediction == F0 prediction
  - F0_MAG prediction == F0 prediction
- adapter off prediction == F0 prediction
- raw observed input은 변경되지 않음
- forward에는 미래 y, clean x0, generator state, true delta, fault mask를 전달하지 않음

`NO_LORA_AUDIT.json`을 별도로 만들고
각 source × seed × arm의 trainable names/count와 LoRA absence를 저장한다.

# 9. 이번 실험의 핵심 질문과 primary contrasts

## Q1. LoRA 없이 MAG 자체가 PEFT로 유용한가?

직접 비교:
- `F0_MAG vs F0`
- `F0_MAG vs F0_PLAIN`

가장 중요한 것은 `F0_MAG vs F0_PLAIN`.
이것이 양성이어야 "LoRA 없이도 magnitude rule의 추가 가치가 있다"고 말할 수 있다.

## Q2. 일반 adapter 자체는 LoRA 없이도 유용한가?

- `F0_PLAIN vs F0`

## Q3. MAG의 효과가 LoRA-pre-adapted base에 의존하는가?

같은 panel/condition에서 다음 improvement를 계산한다.

`plain_gain_F0 = nMAE(F0) - nMAE(F0_PLAIN)`
`plain_gain_B0 = nMAE(B0) - nMAE(B0_PLAIN)`

`mag_gain_F0 = nMAE(F0) - nMAE(F0_MAG)`
`mag_gain_B0 = nMAE(B0) - nMAE(B0_MAG)`

그리고:

`second_stage_interaction_mag = mag_gain_B0 - mag_gain_F0`

양수:
- MAG의 절대 오차 감소가 LoRA-pre-adapted base에서 더 큼.

음수:
- standalone F0에서 MAG의 절대 오차 감소가 더 큼.

또 magnitude rule 자체의 추가효과:
`mag_specific_F0 = nMAE(F0_PLAIN) - nMAE(F0_MAG)`
`mag_specific_B0 = nMAE(B0_PLAIN) - nMAE(B0_MAG)`

`mag_rule_interaction = mag_specific_B0 - mag_specific_F0`

단,
이 interaction을 완전한 인과효과나 모집단 효과라고 부르지 않는다.
기존 B0는 과거 LoRA 학습 비용/파라미터를 이미 사용했기 때문이다.

# 10. 결과 해석 규칙

### Case A
F0_MAG가 F0와 F0_PLAIN보다 반복적으로 좋음:
- `STANDALONE_MAG_SUPPORTED`
- MAG는 LoRA가 없어도 standalone PEFT로 작동하는 개발 근거가 있음.

### Case B
F0_MAG가 F0/PLAIN보다 추가 이득이 없고,
기존 B0_MAG는 B0/B0_PLAIN보다 이득:
- `SECOND_STAGE_DEPENDENCE_SUPPORTED`
- 현재 설정에서는 pre-adapted B0 위 second-stage가 더 타당.
- "수학적으로 LoRA가 필수"라고 쓰지 않는다.

### Case C
F0_MAG가 B0_MAG보다도 좋음:
- 현재 2-stage 설계의 필요성을 재검토.
- LoRA 선행 단계가 불필요할 가능성을 기록.
- 자동으로 joint training이나 새 논문 방향을 시작하지 않는다.

### Case D
둘 다 좋음:
- standalone과 compositional 두 사용법 모두 가능하다는 개발 근거.
- 실제 선택은 정확도·추가 파라미터·누적 학습 비용을 분리해서 판단.

# 12. 누적 비용을 반드시 분리한다

F0_MAG:
- pretrained model
- 새 adapter 8,712 params
- 이번 1,024 update

B0_MAG:
- pretrained model
- 과거 LoRA 294,912 params 및 과거 학습 비용
- 추가 MAG 8,712 params 및 추가 학습 비용

따라서 B0_MAG가 더 좋아도
"LoRA가 반드시 필요하다"라고 단정하지 않는다.

반대로 F0_MAG가 비슷하거나 더 좋으면
더 단순한 standalone 경로의 중요한 근거가 된다.

보고서에 반드시:
- trainable params per stage
- deployed adaptation params
- cumulative adaptation stages
- 이번 새 학습 updates
- 기존 B0 학습은 reused historical cost
를 따로 표시한다.

이번 실험에서는 compute-matched 2,048-update F0_MAG나 joint LoRA+MAG를 자동 추가하지 않는다.
필요하면 결과 확인 후 별도 계약으로만 한다.
