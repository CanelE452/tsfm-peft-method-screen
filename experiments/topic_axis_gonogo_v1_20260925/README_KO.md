# 세 후보의 difficulty-axis go/no-go — 고정 실행 패키지

**목표:** 어떤 좁은 도메인에서 과거 관측으로 측정한 특성에 따라 실제 TSFM 예측 오차가 구분되는지, 그리고 단순한 기존 처리로 충분할 가능성이 있는지 빠르게 판단한다.

**GO는 새 PEFT가 필요하거나 잘된다는 뜻이 아니다.** 일반 LoRA와 강한 도메인 방법을 비교하는 다음 파일럿에 투자할 근거가 있는지까지만 본다. NO_GO도 이 유한 표본·대리지표·예측 길이의 범위로 제한한다. 세 후보 모두 합의 없이 adapter를 새로 만들거나 학습하지 않는다.

## 한 번 실행

ZIP을 저장소 밖 새 폴더에 풀고, 실제 `CanelE452/tsfm-peft-method-screen`의 루트에서:

```bash
python3 -B /실제/압축해제경로/topic_axis_gonogo_v1_20260925/run.py --repo "$PWD" --publish
```

코드·설정·manifest는 변경하지 않는다. 기존 `.venv/bin/python`으로 재진입한다. 별도 설치·모델 다운로드·학습·자동 재실행은 없다. 필요 라이브러리 또는 모델 캐시가 없으면 BLOCKED로 남긴다.

풍력은 공식 Figshare의 KDD 부분 ZIP을 크기 확인 후 가져오는 경로가 있다. 다운로드 예산을 넘거나 파일 구성이 달라 자동 접근하지 못하면 그 후보만 BLOCKED다. 이미 갖고 있는 공식 KDD 자료를 사용할 때만 다음 **경로 인자**를 추가할 수 있다.

```bash
# sdwpf_245days_v1.csv 및 TurbID,x,y 열이 있는 위치 파일을 이미 보유한 경우
python3 -B /실제/압축해제경로/topic_axis_gonogo_v1_20260925/run.py --repo "$PWD" --publish \
  --wind-csv /실제경로/sdwpf_245days_v1.csv --wind-locations /실제경로/turb_location.csv
```

또는 `--wind-archive /실제경로/sdwpf_kddcup.zip`. 전체 SDWPF의 다른 스키마를 이름만 바꿔 대입하지 않는다. CLI가 변환 코드를 새로 만들지 않는다. 경로 없이 실행해 BLOCKED가 된 뒤 이 인자를 붙여 재실행하지 말고 결과를 반환한다.

## 세 독립 트랙

| 트랙 | 데이터·예측 | 과거에서 계산하는 후보 축 | 단순 대조 |
|---|---|---|---|
| 풍력 | SDWPF/KDD의 고정 터빈 부분집합, 6시간→1시간 | TRAIN에서 추정한 방향 구간별 이웃 관계의 시간적 변화량 | 지속값, 일반 회귀, 같은 정보에 이웃 요약을 추가한 회귀 |
| 호흡 | BIDMC RESP, 64초→8초, 5Hz 구간평균 | 과거 봉우리 사이 간격의 강건한 변동계수 | 마지막 완성 주기 반복, 일반 회귀, 주기 정보 추가 회귀 |
| 좌표 | ETH/UCY의 보행자 평면 궤적, 8→12표본 | TRAIN 방향 분포에 비해 현재 이동 방향이 드문 정도 | 등속도, 일반 회귀, 좌표 정렬 후 F0 |

좌표 트랙은 자연 방향 희소도와 별도로 **같은 궤적을 45/90/135도 회전시킨 대응 실험**을 수행한다. 이것은 표현의 민감도이지 운동 자체의 본질적 복잡도가 아니다. 관절 데이터가 아니라 이전 제안에 포함된 보행 궤적으로 범위를 고정했다.

풍력에서 Ndir는 나셀 방향의 대리 신호이고, 익명 위치 좌표의 동·북 방향은 확인하지 않았다. 따라서 거리로 이웃을 정하고 TRAIN의 경험적 관계를 사용한다. **물리적 후류 그래프를 식별했다고 주장하지 않는다.**

## 이전 실패를 반복하지 않는 규칙

- 단순 회귀가 좋아야 F0를 실행하는 문턱을 두지 않는다. 데이터·구현이 유효하면 항상 실제 Chronos-2 F0를 평가한다.
- 어려움의 낮음/중간/높음 경계는 TRAIN의 1/3·2/3 분위수로 고정한다. TEST 오차를 보고 경계나 방향을 바꾸지 않는다.
- TRAIN은 회귀/관계 추정, CAL은 정규화 강도·단순 대조 선택, TEST는 최종 후보 판정에만 쓴다.
- 과거의 크기·변동·추세 같은 경쟁 설명을 CAL에서 적합한 모델로 보정한 차이도 함께 확인한다. 인과관계 증명은 아니다.
- 환자·날짜·장면을 불확실성 단위로 쓴다. 겹친 창, 터빈, 회전 복사본을 독립 표본으로 세지 않는다.
- 데이터/다운로드/시간/모델 실패는 BLOCKED 또는 구현 오류로 남긴다. 과학적 NO_GO와 혼동하지 않는다.
- 원자료와 모델 파일은 `.cache/`에만 둔다. 공개 push는 공급한 소스와 작은 점수·설정·오류 기록만 한다.

## 결과

`results/topic_axis_gonogo_v1_20260925/run_<UTC>/ALL_TOPICS.json`에 세 트랙 결과가 모인다. 각 트랙의 `RESULT.json`, `PRE_TEST_SEAL.json`, `SCORE_ROWS.csv`, `DOWNLOADS.json`, 원시 오류 기록을 함께 본다.

`--publish`는 새 패키지와 이번 결과의 정확한 파일 목록만 commit/push한다. 기존 staged 변경·다른 저장소·HEAD 변경·원격 충돌이 있으면 중단한다. `git add .`, reset, rebase, force-push는 하지 않는다. 생성 CSV는 LF이며 console의 공백 때문에 과학적 계산을 재실행하지 않는다.

## 실제로 검증된 범위

`AUTHOR_VALIDATION/VALIDATION.json`과 `UNIT_TESTS.txt`를 참고한다. 작성 환경에서 실제 Chronos/전체 공개 원자료를 실행했다고 주장하지 않는다. 알고리즘·누출 반례·입출력 형상·작은 합성 자료 전체 흐름·로컬 bare Git 게시 검사를 수행했다. 실제 세 후보의 과학적 결과는 Ubuntu에서 처음 계산한다.
