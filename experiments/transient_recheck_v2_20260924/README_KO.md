# 전환 이력 재검증 v2 — 고정 코드 실행 패키지

## 목적

기존 BOPTEST 히트펌프·바닥난방 자료에서 **허용된 과거 범위와 미래 명령 계획을 맞춘 뒤에도, 운전 이력이 추가 예측 가치를 보이는지** 한 번만 재평가한다. 새로운 PEFT, 새로운 복잡도 점수, 새 시뮬레이션을 만들지 않는다.

이번은 이미 확인한 v1의 부정적 결과를 본 뒤 만드는 **후향적 설계 수정·개발 평가**다. 결과가 좋아져도 v1 결과를 지우거나 독립 확증으로 바꾸지 않는다. `NO_HISTORY_SIGNAL`이라는 과도한 판정도 사용하지 않는다.

## 실행

ZIP을 저장소 밖의 **새 폴더**에 풀고, 실제 `CanelE452/tsfm-peft-method-screen` 루트에서 다음 한 번만 실행한다.

```bash
python3 -B /실제/압축해제경로/transient_recheck_v2_20260924/execute.py --repo "$PWD" --publish
```

압축해제 경로만 바꾼다. 코드는 저장소의 기존 `.venv/bin/python`을 사용한다. NumPy 외에 새로운 수치 패키지를 요구하지 않는다. 설치·다운로드·Docker·GPU·Chronos·LoRA 실행은 없다. 사용자 저장소가 아니거나 기존 staged 변경이 있거나 remote/main과 local HEAD가 다르면 자동 조정하지 않고 중단한다.

## 기존 자료만 읽는다

기준 자료 커밋: `948134f36a49300f6ca0c405f4757760d8f0cfdc`

```
results/transient_difficulty_screen_v1_20260924/run_20260924T075030Z/episodes/
```

0~4는 TRAIN, 5~6은 DEV다. **7번 보류 구간은 열지도, 해시를 계산하지도, 채점하지도 않는다.** 파일 누락·해시 불일치 시 새 자료로 대체하지 않는다. 소스 파일 및 기존 결과를 덮어쓰지 않는다. 최근의 다른 연구 작업은 건드리지 않는다.

원자료는 같은 건물 시뮬레이터의 날짜·명령 일정이 다른 구간이다. 독립적인 건물 8개가 아니다. 이미 노출된 TRAIN 자료를 쓰므로 새로운 독립 연구 증거라고 부르지 않는다.

## 이번에 수정한 핵심

### 과거 정보 범위

모든 특징은 정확히 `[원점-context, 원점]`에서만 계산한다. context 밖의 8시간 전 온도나 6시간 명령 통계를 몰래 사용하지 않는다. 범위 밖의 시차 특징은 제외하며, 마지막 명령 전환이 context 이전이면 경과시간을 context 길이로 제한하고 검열 여부를 함께 기록한다.

v1의 원점 위상 `context-dt + k*stride`는 유지한다. 단, 최초 원점처럼 완전한 inclusive context가 없는 원점만 제외한다. 모든 원점을 제어 경계로 옮기지 않는다. 제거 개수와 실제 원점 시각은 저장한다.

### 미래 명령 계획

세 회귀 구성 모두 예측 구간 전체의 동일한 명령 계획을 받는다. 원 수집 코드의 deterministic schedule을 재구성하고 당시 저장된 schedule SHA-256과 대조한다. 미래 정답이나 사후 관측 명령열을 계획으로 만드는 방식은 쓰지 않는다.

기존 수집기는 일정을 생성한 뒤 시뮬레이션을 진행했다. 다만 발행 시각이 찍힌 운영 로그는 없으므로 **재구성된 시뮬레이션 계획**으로 표현한다. `t`의 저장 명령은 그 시각까지의 직전 구간에 적용된 값이다. 계획과 실제 저장 제어량의 정렬을 고정 규칙으로 검사하며, 불일치하면 잘 맞는 shift를 탐색하지 않고 중단한다. 보조 펌프·팬이 `compressor>0`과 같다는 원 수집 계약도 검사한다.

### 비교군

| 새 코드 이름 | 공통 부분 | 차이 |
|---|---|---|
| `CURRENT_PLAN` | 제한된 과거 온도 특징, 현재 명령, 전체 미래 명령 계획 | 과거 명령을 제거한 정보 소거 대조 |
| `HISTORY_SUMMARY_PLAN` | 위와 같음 | 제한된 과거 명령 요약 통계·경과시간 추가 |
| `HISTORY_LAGS_PLAN` | 위와 같음 | 같은 제한된 과거 명령을 시차 벡터와 ON/OFF 시차로 제공 |

`CURRENT_PLAN`이 과거 명령을 받지 않는 것은 **의도된 정보 소거**다. 세 방법이 완전히 같은 정보 표현을 받는 PEFT 비교라고 부르지 않는다. 두 HISTORY 방법은 같은 원시 이력을 다른 표준 선형회귀 특징으로 표현한다. 세 번째 방법은 요약 통계가 정보를 놓친 경우를 구분하기 위한 단순 시차 회귀 대조이지 신규 방법이 아니다. 마지막 온도 유지 예측 `PERSISTENCE`도 함께 보고한다.

## 표준 회귀와 시간순 검증

리지 목적식은 표준 `||Y-XB||² + alpha||B||²`다. 평균·표준편차·타깃 중심화는 해당 학습 구간에만 맞춘다. 알파 후보는 `0.01, 0.1, 1, 10, 100, 1000, 10000`의 고정 7개다. 이번 범위의 고정 탐색 예산이지 검증된 최적 범위가 아니다. 경계값이 선택돼도 자동으로 범위를 늘리지 않는다.

TRAIN 구간 2·3·4를 순서대로 평가한다. 예를 들어 3번 구간을 평가할 때는 0~2만 학습하고, 알파도 그 안의 과거→다음 구간 검증으로 고른다. 3번의 오차로 3번 예측용 알파를 고르지 않는다. 최종 DEV용 모델은 0~4만으로 적합한다.

세 방법 모두 같은 알파 선택 기회를 받는다. 추가로 **알파=1 고정 결과도 남겨** 정규화 선택의 영향을 분리한다. 정규화 선택 지표는 전체 원점 MAE이며, 전환 구간 결과를 보고 알파를 다시 고르지 않는다.

모든 다섯 과제의 최종 모델·알파·설정·소스 TRAIN 해시를 `PRE_DEV_SEAL.json`에 봉인한 **뒤에만** DEV 5·6을 읽는다. DEV에서 모델/과제/패널/알파를 다시 고르지 않는다. DEV 두 구간만으로 모집단 신뢰구간이나 통계적 유의성을 주장하지 않는다.

## 전환 구간 평가

전체, 최근 과거 전환, 계획에 전환 포함, 둘의 합집합, 둘 다 없음, context 안 다중 전환을 별도로 보고한다. 공급수온 최근 창은 15분, 실내온도는 1시간으로 고정한다.

이는 **[추정·미검증] 운영상 구분 창**이다. 물리 시상수나 열적 정착 경계를 추정했다는 뜻이 아니다. `NO_RECENT_OR_PLANNED_CHANGE`도 실제 정상상태를 보장하지 않는다. 결과에 맞춰 경계를 바꾸지 않는다. 패널에 표본이 없으면 `NO_PANEL_SUPPORT`이며 0 오차로 처리하지 않는다.

모든 지표는 원점별 예측 경로 오차 → 구간별 평균으로 계산한다. 구간 간에는 동일 가중치를 사용한다. 원점별 정답이 겹치는 것을 독립 표본 수로 세지 않는다. 작은 조건부 패널은 지원 원점 수와 구간 수를 함께 표시한다.

## 실행 예산

새 시뮬레이션 0, F0 추론 0, LoRA/PEFT fit 0, GPU 0.

계수 적합 상한은 `5개 과제 × 3개 구성 × (4개 시간순 검증 fold × 7개 알파 + 최대 8개 재적합) = 540`이다. 여러 예측 시점은 하나의 다중출력 적합으로 센다. 각 알파 경로는 SVD를 공유한다. 실패 시도도 원장에 센다. CPU 2 thread, worker 최대 30분, 공개 결과 최대 64MiB, 비공개 회귀계수 최대 128MiB로 제한한다. 검사 테스트의 합성 적합은 별도로 기록하며 사용자 자료 fit 수와 섞지 않는다.

## 결과 해석과 종료

정상 종료 토큰은 **`COMPLETED_BOUNDED_RECHECK`**로, 연구 성공을 의미하지 않는다. 양성/음성/혼재 모두 그대로 저장한다.

- 요약과 시차 회귀 모두 개선하면: 이 설정에서 이력의 추가 가치 후보. 아직 LoRA의 한계나 특화 PEFT 우수성은 아니다.
- 시차만 개선하면: 요약 표현 또는 추정 방법의 한계가 가능한 설명이다. 과거 이력 전체가 무용했다는 결론은 안 된다.
- 튜닝 전후가 크게 다르면: 고정 alpha의 영향이 가능하다. 타깃·정보·패널 변경 효과까지 함께 바뀌었으므로 v1→v2 차이를 alpha 한 원인으로 돌리지 않는다.
- 둘 다 불리하거나 날짜마다 반대면: 현재 검토한 회귀·자료 범위에서 추가 가치 미확보/불안정. 정보 부재의 증명은 아니다. 성공할 때까지 재실행하지 않는다.

어떤 결과라도 본학습이나 다른 후보를 자동 실행하지 않는다. 다음 연구 판단은 push된 원수치와 코드에서 사람이 검토한다.

## Git과 실패

CLI는 코드 수정·재실행을 하지 않는다. 검사는 실패해도 원시 오류를 보존하며, 안전한 Git 상태이면 실패 결과도 같은 방식으로 게시한다. 기존 staged 변경, 실행 중 HEAD 변경, 인증·네트워크 오류이면 자동 복구하지 않는다.

패키지 파일과 해당 실행의 작은 결과 파일만 정확한 allowlist로 commit한다. 저장소가 `*.log`를 무시하므로 허용된 작은 로그에 한해 `git add -f -- <정확한 파일들>`을 사용한다. 이는 force-push가 아니다. `.pt/.pth/.npz`, 원자료, 무관한 변경을 강제 stage하지 않는다.

실행 완료 receipt는 압축해제 폴더 **바깥** `transient_recheck_v2_20260924_EXECUTION_RECEIPT.json`에 남는다. 같은 패키지를 경로만 바꿔 재실행하는 것도 저장소의 one-run marker로 차단한다.
